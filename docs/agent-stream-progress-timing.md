# 模型流式进度与实时鉴权

模型响应的逐片段消费与后台 watchdog 共用 `ModelStreamGuard`。普通片段和进度保存复用同一次成功鉴权，缓存从鉴权完成时起计时，最长 0.5 秒。watchdog 每轮仍强制读取当前权限、任务状态和资料绑定；错误在流消费与 watchdog 之间共享，逐片段仍检查任务期限。

开始请求、校验回答、完成和失败的进度保存均强制重新鉴权，不复用片段缓存。暂停、取消、撤权和资料修订检查仍使用原有检查函数与数据范围。进度保存的 0.6 秒节流从保存完成时起计时，最终计数和思考尾部在终态保存时刷新。

普通进度保存不能再次强制鉴权：当一次完整校验超过保存间隔时，watchdog 校验和保存校验会串行排队，令每个模型片段重复等待完整校验，即使模型服务已经生成全部响应，页面仍会每隔数秒仅收到几个字符。

回归测试覆盖耗时鉴权与保存、watchdog 刷新后连续片段、校验前即时撤权、暂停、取消、任务期限以及完整终态计数。该调整不改变 API、权限判断条件、业务数据目录和科研数据内容。

逻辑推理项目的轻量、标准、深入均开启模型思考，分别传递 `low`、`medium`、`xhigh`，受当前模型能力和管理员策略约束。工作流卡片在收到真实思考后自动展开，用户可自行收起；历史未开启思考的请求明确显示原因。

算子提交前的大结果读取、批准范围复核与输入准备在数据库写事务之外执行，允许计算 worker 持续更新心跳。获批操作表使用短事务保留唯一资源及停止检查；最终提交重新锁定工作流、核对计划摘要、暂停、取消、当前权限、输入和算法版本，再原子保存真实任务与工作流进度。环境就绪仍要求真实且未过期的 worker 心跳。

聊天及科研意图路径的思考片段与答复预览同样复用当前请求的 `ModelStreamGuard`；普通定时保存复用片段的成功检查，watchdog 强制检查实时权限。思考每 0.6 秒或累计 500 字符保存，答复预览每 0.3 秒或累计 256 字符保存。保存节流从数据库写入完成时计时，最终刷新和达到批量阈值的保存重新鉴权；停止、撤权和达到期限后不发布未保存尾部。
