# 历史计算结果清理（2026-10-16）

数据资源 → 文件管理 → 选择文件 → 删除所选，现在先检查真实依赖，再显示确认框。确认框逐项说明可删除范围；用户点击“确认删除”才执行。

## 清理范围

- 没有依赖的资源沿用现有删除行为，删除目录记录和受平台管理的文件。
- 标记为计算结果的资源，可以在确认后解除已经结束的计算任务及科研工作流的存量引用。计算任务、工作流、原方案、审核记录、步骤和检查点继续保留。
- 删除凭据保存资源名称、编号、来源、所属项目、操作者及时间。计算输入快照和工作流计划携带凭据，操作日志另留完整记录。
- 工作流的可执行输入与结果列表移除已删除资源，历史方案和步骤保留原文供溯源。计算任务输入外键显式置空，界面提示重新选择输入。
- 已删除的目录结果显示“目录数据已删除”，不再提供失效的目录或地图入口。独立计算输出仍遵循现有有效期，可在有效期内预览或下载。
- 相关普通智能体和科研对话可恢复已结束的历史记录，过期的参数卡不再作为可运行计划展示。只有平台正式删除凭据支持的历史资料可读；仍存在的资料、当前数据类型、本人隐私和知识权限继续核对，活动任务不走历史恢复。

原始上传数据的依赖保护保持原规则。尚未结束的计算、入库、科研工作流、普通智能体任务（包括等待回答）继续阻止删除。成果展示、已保存工程和专题图的关联也继续保护，确认不会绕过这些关联或项目和个人隐私权限。

## 确认与一致性

预览接口 `POST /api/catalog/resources/delete-preview/` 返回逐项状态及签名确认凭据。凭据绑定用户、当前项目、所选资源集合和历史引用快照，有效期10分钟。删除接口仍为 `POST /api/catalog/resources/delete/`，增加 `historyConfirmationToken`。

批选时可以部分成功，受保护项目在结果列表中说明原因。确认之后新增活动引用会立即阻止删除；资源、方案或历史引用变化时要求重新预览。重复请求不重复清理已经删除的数据。

每项删除在独立持久事务中完成，历史解除、资源记录、存储操作和日志同成功或回滚。`ComputeInput.resource` 改为可空，仍保留 `PROTECT`，通过业务确认后才显式解除历史外键。上线需要执行新增 `compute/0006_nullable_historical_input` 迁移。

## 本机验证

- 资源删除、历史清理和对话恢复集成测试：61项和8个子例通过；包含已入库输出仍处于模型续处理时的保护，以及本人隐私、数据类型撤权和正式删除凭据检查。
- 数据目录浏览器交互：10项通过，覆盖预览、确认、部分成功、活动保护、取消、切项目和迟到响应。
- 定向后端格式及静态检查、前端静态检查、Compute迁移一致性通过。

测试使用临时资源、数据库和文件，不删除业务数据。正式是否上线及服务器验收以本次发布回执为准。
