# 地质成果智能检查与修正演示

## 演示操作

1. 登录后进入“成果展示”，选择“地质成果智能检查与修正”的“开始体验”。系统切换到有权限的地质项目，打开智能体并带入任务文字。
2. 发送任务。智能体读取“待检查地质图”“制图覆盖资料”和“专家知识检查规则”，查询专家知识，调用检查算法。对话中显示简短判断，已完成过程可以展开查看。
3. 在“建议修改”中查看当前状态、建议状态、修改依据和范围。点击“在地图上查看位置”可打开地理工作台。此时地图仍为待检查状态，橙色表示建议范围。
4. 勾选需要修正的建议并批准。也可拒绝并留下意见。系统只执行当前获批范围；改变计划后需要重新批准。
5. 修正完成后，智能体读取实际输出并复核。点击工作台入口，在双图中对照“待检查地质图”和“修正后地质图”。拖动、缩放任一地图，两边保持同步；点击橙色修改范围查看前后状态与原因。
6. 在对话末尾或双图下方预览、下载“检查报告.md”。地图、差异图层与统计表可从统一文件区下载；已经保存的结果位于本项目“数据资源 → 计算结果”。报告也可以单独保存入库。

刷新页面会恢复服务器保存的判断、建议、批准与计算记录。重新演示时从成果展示开启新会话，仍使用同一份待检查资料，之前的结果保留。

也可以直接在地质项目的智能体中发送：

> 请检查这个演示案例的待检查地质图，查阅专家知识，核对完整覆盖和地层时代属性。先展示问题、依据和建议范围，等我批准后再修正，最后复核并给我地图和检查报告。

科研工作流的参数表单保留，可手选输入、算法参数和知识范围。

## 案例与知识

主问题是完整制图范围内的内部漏填。项目整理规则要求：覆盖资料明确完整覆盖、排除了水体与未调查区，且内部空白整个周界由同一有效地质图斑包围。算法检查这些条件，建议沿用唯一包围图斑的稳定类别填补。面积仅用于筛查。多类周界、多个宿主、边界空白或例外区需要补资料复核。

辅助问题是地层名称与时代属性的一致性。专家知识引用《中国岩石地层名称辞典》八宝山组条目06-63-0717：青海东昆仑南坡，时代T3，即晚三叠世。采用该条目定义且没有相反可靠定年证据时，建议更新矛盾的时代属性，保留类别、岩性与边界。

这两条知识分别保存名称、范围、条件、异常表现、处理方式、例外和来源。完整覆盖规则明确标为项目整理规则。图件中的地层、地区和时代字段按资料整理口径形成演示条件；展示定位为演示案例。

## 老师展示口语稿

“这张地质成果准备提交，我们先让智能体检查一下。它会先读地图，再查专家知识。这里查到一处内部漏填，另一处地层时代与所用辞书定义不一致。

“现在它还没有改地图，而是把发现、依据和建议范围交给我。我可以看地图，也可以只批准其中一条。我们批准选中的建议。

“接下来是算法实际修正，算完以后，结果还会返回智能体重新检查。这里左边是待检查图，右边是修正后图，橙色边界告诉我们实际改了哪里。点击以后能看到改前、改后和原因。

“最后把检查发现、知识依据、我的批准、实际修改和复核结论放进一份短报告。图层、统计表和报告都能保存下来，下次打开仍然能查到。”

## 实现与复现记录

新流程标识`geology_map_review`。复用持久会话、科研工作流、知识检索、计算任务、结果入库和报告文件服务。算法为`geology-map-check`与`geology-map-correct`，具体版本、输入、参数与校验和固定在每次真实任务中。

运行顺序固定为知识查询、检查、提议、用户批准、修正、复核和模型解释；问题位置、知识引用、类别与时代、理由及统计来自当次数据和工具返回。编辑算法重新读取输入与规则，核对获批操作，不接收模型任意坐标覆盖。

内部准备由`scripts/geology_review_data.py`生成三项运行资料和独立验收目录。`prepare_geology_review_case`只接收运行清单与专家知识包，登记草稿算法；通过隔离计算环境的真实试运行后才发布。独立验收资料不登记为平台资源，不进入模型、检索或算法输入。

类别以`class`为稳定键，保持`name/code/path`一致；同名不同编号分别统计。面积由米制投影重新计算，GPKG输出供地图查询，CSV保存变化与分类统计。

本轮测试、真实模型运行及服务器生效情况以交付回执为准。
