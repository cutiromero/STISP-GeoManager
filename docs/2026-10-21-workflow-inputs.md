# 地质检查资料选择与演示操作

## 页面操作

在逻辑推理项目进入“科研智能体 → MH-workflow → 地质成果智能检查与修正”。

1. 点“预设”，恢复当前项目活动地质图、覆盖资料、专家规则、参数和知识选择。
2. 手动选图或改参数后，可点“按名称匹配资料”重新匹配适合当前角色的资料。唯一匹配才替换；缺项和重名会提示，保留兼容的人工选择，不把规则表当作地质图。
3. 点“生成执行计划”，核对本次资料、参数、知识选择及算法版本。修改这些设置后须重新生成，不能拿旧计划执行新设置。
4. 确认检查计划后，智能体实际检索知识并调用检查算法。每项修改建议展示位置、前后状态、知识修订、出处及拟用算法。
5. 用户批准选中建议后执行修正，读取实际结果继续复核。完成后可打开地图、预览或下载检查报告。没有可修正项时给出检查结论或补证据建议。

“预设”恢复的是本案例配置；“按名称匹配资料”帮助选择名字明确的输入，保留用户参数。两者都不替用户批准地图修改。

## 三类输入的含义

| 输入 | 用途 | 入库格式与要求 |
| --- | --- | --- |
| 待检查地质图 | 要检查的分类面图 | GPKG、GeoJSON/JSON，或完整Shapefile压缩包ZIP；稳定图斑ID、class及分类映射、地层、地区、时代字段 |
| 制图覆盖范围与例外 | 明确哪里应完整制图，哪里允许空白 | 同上面矢量格式；完整覆盖、水体/未调查区例外、地区及来源字段 |
| 专家规则 | 算法可执行的检查条件和允许操作 | CSV、TSV、XLS、XLSX结构化表；适用条件、例外、地区、地层、来源及知识定位字段 |

文件后缀只说明格式。入库后的实际字段、面几何和坐标系还须符合协议；创建前后端校验，运行算法继续核对逐行内容、空间条件和获批范围。具体字段见`backend/apps/agent/geology_input_validation.py`和已发布算法清单。

## 知识、模型与算法怎样分工

专家知识保存带来源的定义、适用条件和例外。专家规则把条件整理成算法能执行的表；模型对照检索到的知识与实际地图，提出受约束操作。算法计算问题、执行获批修改并重新统计，模型再读取真实输出解释。

当前阶段顺序固定为知识查询、检查、建议、批准、修正、复核和解释。具体疑点位置及可执行操作来自本次输入和检查结果，运行链路不读取独立验收参考图。此版本支持完整覆盖条件下的内部漏填和适用地层的时代属性一致性；接入新图时需要整理同协议资料及适用知识。

具体知识编号和修订与建议绑定，报告逐项列出真实任务的算法名称及版本。规则表目标值与知识正文的完整语义一致性目前由模型比较；进一步扩展规则需整理明确的结构化专业约束。

## 登录封面与图层

封面恢复三张背景轮换与持续光带、网格动画；布局保持当前版本。页面隐藏或用户开启系统“减少动态效果”时暂停动画。

地理工作台对同一原始数据只保留一个图层。再次加载会显示并定位已有图层，并发点击共用加载操作；删除图层后可重新加载。具有不同筛选条件的空间查询结果仍是不同范围的派生图层。
