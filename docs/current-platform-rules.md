# 当前有效平台规则（2026-11-10）

本页优先于设计与实现文档中的历史阶段记录。

- 进入系统先到地理工作台。顶部主要顺序为地理工作台、智能体、业务流、数据资源、计算中心、知识库、成果展示；随后为其余原有入口，项目管理位于后台。数据分析在数据资源下拉中，数据与成果导入仅保留该下拉入口。智能体入口对游客和低权限账号可见但不可使用，正式权限仍由后端核验，橙色突出智能体。业务流承接原数据资源的蓝色强调，数据资源恢复普通模块样式。
- 顶部第五个模块为计算中心模块；后台 `/admin/compute` 维护算法分类、算法资源、不可覆盖的版本和当前项目任务。管理员按统一清单上传、试运行、发布新算法，不按 NDVI 等单一算法硬编码业务页面。
- 计算输入、任务及结果固定一个项目；公开已发布算法可在私有项目调用。数据无需先加载到地图；空间查询仍遵循已加载图层规则。结果下载需数据导出权限，入库需数据新增权限，只能存入任务所属项目。
- 上传算法仅在受限 Linux 容器执行，禁止直接在应用主机运行。环境不可用时停止提交与试运行；真实试运行通过才允许发布。2026-09-19 本机 WSL2、Docker、计算镜像及独立 worker 已完成部署和真实验收，四个示例算法已发布。公开项目附带明确标注为人工构造的演示输入与结果，详见 `2026-09-19-compute-deployment.md`。
- 每次仅在一个具体项目操作，不提供 all / 全部可访问。用户和游客默认可访问“公开”项目（ID 1，内部代码 default）；超级管理员可按用户关闭公开访问，并分配至少一个启用私有项目。登录后的业务请求、知识检索、任务恢复与邀请分享遵循同一范围。超级管理员始终访问全部项目。
- 数据、工程、成果必须归属一个项目；上传必须显式选择有权访问的项目。角色控制操作权限，不通过历史 accessGroupIds/audienceGroupIds 再分配对象可见性。
- 成果展示的生态监测大屏`/results/ecology-monitor`由后端项目功能`ecology_monitor`控制，支持单项目和全局开启。配置显式选择胡杨模拟源或真实遥感产品，并可启用互花米草、野火场景。未开启项目显示提示，开启但无配置或成果时显示空状态，不回退其他项目。胡杨点位与研判保持模拟标签；遥感场景只展示当前项目可见成果，缺失时间/统计不补造，地图及全部来源重验权限，新模型成果沿用计算中心质量门禁与标准入库。开关、配置和接入见`ecology-monitor.md`。
- 科普与团队动态独立于项目。已发布内容公开；正文、封面、附件说明和新附件随保存一起提交。草稿、下架内容保留现有内容管理权限规则。
- 数据目录分地理数据、非地理数据和计算结果。用户上传按坐标自动归为地理/非地理，计算中心与智能体的成果入库后统一进入计算结果；资源原有空间属性保留。空间查询仅选择已加载矢量来源，查询语义保持现状。
- 工程摘要分页，加载时读取详情；更新须带最后读取的 updatedAt，冲突返回 409。
- 工程默认创建者私有；同项目成员和普通平台管理员不自动可见，显式邀请并接受后才授予该工程只读。列表、搜索、直接 ID、后台和来源工程加载遵循同一边界；超级管理员保留当前项目管理能力。历史工程按现有所有者应用此规则，不删除工程或聊天。
- 导出沿用现有格式和 DPI。底图选择随工程保存，主图、格网、比例尺和区位框使用同一实际输出范围。
- 备份是全平台维护：平台备份包含数据库、配置、媒体、上传、所有项目内容、持久成果；科研备份包含公开及所有私有项目目录，与当前项目无关。缓存和备份归档不重复备份。

用户暂缓 R01–R03；R04 保持当前查询语义；R05 不改现有科普文章、学习链接和演示内容策略。
# 2026-09-21 数据可见性、GPU 与智能体规则

- `DataResource.owner_only=false` 是上传默认值，项目成员按现有项目授权可见；切换为 `true` 后只有上传者和超级管理员（含平台超级用户）可读。平台管理员的后台数据管理权限不改变该隐私边界，资源目录、资源详情、表格分析、图层、栅格瓦片、导出、工程快照、计算输入和数据智能体都必须使用同一资源访问判定。
- 图层、栅格数据集和计算任务不得通过直接按 ID 查询绕过资源可见性。栅格列表在当前项目使用统一资源可见性筛选，超级管理员和平台超级用户可查看其中已绑定资源及未绑定资源的数据集；普通成员和平台管理员仍遵循资源状态与仅上传者可见规则。任务提交时和 worker 冻结输入时都要重新检查上传者对资源的访问权；撤权后任务停止或拒绝读取。
- 智能体会话和运行结果持久化，切换页面后从服务器恢复；浏览器存储只作为当前会话提示，不能替代服务端历史。科研智能体可读取授权业务资料，准备仅含数据引用、查询和配色的个人地图工程，提供当前项目站内按钮；原始文件、属性、几何和资源默认样式保持只读。展示工具由 mapDisplayEnabled 及原有加载、配色、工程权限共同控制，计算算子另由 operatorEnabled 控制；任意代码、直接 SQL、路径和权限修改不开放。工具步骤策略上限仍为 64。
- 服务器 GPU 展示只读取主机现有 `nvidia-smi`，支持单卡、多卡及 CPU-only（无 GPU 时不显示 GPU 卡片），不得改变模型服务或 GPU 进程配置。
- 服务器存储卡片分别展示检测到的物理硬盘容量、平台所在分区的已用与总容量，以及平台当前可用空间；分区容量使用 GiB/TiB。识别到物理盘不表示该盘已分配给平台，使用率只对应实际统计分区。


# 2026-11-10 业务流与双智能体审核

- 业务流是独立模块，定义完成科研任务所需的资料规范、已发布算子、依赖节点与成果要求。项目专用业务流仅在所属项目可见，公开项目登记的通用业务流供各项目使用，逻辑推理仅在核地院逻辑推理项目可见。业务流目录只描述能力，不授予新的数据、模型、算子或写入权限；登记和版本发布由超级管理员管理，执行仍逐边界重验当前账号、项目、资料与工具权限。
- 发布版本不可覆盖。每次启动冻结实际版本、输入资料和执行选择；新版本不会改变已有任务。业务流复用AgentWorkflow、现有workflow_worker和计算/入库服务，不建立平行的科研任务或导入调度器。
- 通用research_flow逐节点可选独立AI审核、人工门禁或两者均不启用。审核模型使用独立请求和上下文，返回具体理由与返修要求；执行者在发布版本的有界次数和当前预算内返修。审核通过不构成人工批准；声明必须人决定的节点只有用户可批准或退回。用户的暂停、停止与有效批准不被迟到模型响应覆盖。
- 专业逻辑推理新任务统一从业务流入口发起，保留原有科学算子与重要批准边界。目录映射实际inputs、check、apply、recheck、relations、prospect、finish节点；资料确认和处置批准由用户决定，只在apply和finish的实际模型决策边界可启用独立AI审核。专业详情使用紧凑子面板，整体七节点进度和主要控制操作由业务流统一展示。
- 智能体会话以真实父会话/运行关联展示业务流主干、执行与审核双方状态、返修原因和等待人工决定的位置。状态来自持久运行和事件，不能用动画、模型自报完成或重复启动任务代替真实进度。
- 通用算子可通过inputBindings使用本次执行的初始角色或依赖祖先的真实输出；中间成果沿用request_output_import、ComputeImport及质量门禁，ready后才交给后续算子。不得借连线复用他人或外部任务结果；人工节点批准不把needs_review质量状态变成通过。
- 通用启动parameters仅提供nodeParameters（算子节点ID到manifest参数值）；不接受任意根级参数、未知节点或未声明参数。节点默认值与本次值合并后仍通过计算中心校验。专业逻辑推理沿用既有参数和上传批次规则。get_platform_link(page=business_flows)只生成当前项目目录入口，启动业务流使用真实版本与输入，不因打开页面自动执行。

## 通用业务流输入协议（2026-11-10）

所有业务流共享输入适配机制：按真实类型、字段、版本和声明的目标语义匹配已发布转换能力，不按地质案例、资料名称、矿物白名单决定能否执行。输入预检不计算；实际转换沿用计算中心队列、权限和预算，派生输入仅供产生它的工作流使用，原始资料不可修改。新增领域需登记对应转换能力，未知含义需确认，不能将任意格式转换当成科学意义等价。

业务流资料衔接允许Agent根据实际资料编写简短Python，沿用统一输入准备服务和真实计算队列；已有工具可用时优先复用。独立低权限脚本只读本次快照、写派生结果，固定科学算子、流程与人工门禁保持冻结。代码、版本和诊断按需审计；缺少必要含义才请求说明，说明不等于批准。

## 逻辑推理节点执行与思考设置（2026-11-11）

逻辑推理新发布的main_agent模式由一个任务级主执行循环选择合法目标、调用工具、读取真实结果并持续推进七个目标；节点不启动独立执行智能体。短技能随发布版本固定，任务历史与台账仅保留短摘要及成果引用，必要时按需回顾完成目标。输入绑定及清单允许的参数按真实资料适配，核心登记算法、规则来源和实际处置批准范围保持受保护；每次改变方案重新预检。失败按诊断恢复，平台故障或预算不足等待，重试不重置计数。默认标准medium，可选轻量low和深度xhigh，执行、独立审核、返修和归纳均继承父运行设置。未声明新模式的历史版本及关闭Agent的任务保留原执行方式。

## 业务流主执行、上下文与报告（2026-11-12）

新业务流以一个主执行智能体贯穿任务，非必要不增加执行子智能体；独立审核只在必要边界保留。节点验收核对真实输出，不要求逐字复述条件；同一诊断允许不同实际方案补救。输入服从实际模型和用户配置，不叠加固定32K角色上限。历史优先自动压缩为短行动与成果引用，完整科学事实及批准依据不交给有损摘要。节点累计时间与单次请求时限分别计量。主执行者撰写报告综合分析，下载文件必须包含已接受分析，平台模板只组织内容及附入实际统计。详见 `business-flow-development-standard.md`。
