# 领域知识库与智能编排

## 用户入口与处理链

“时空科普”继续位于 `/knowledge`，使用用户提供的八篇新版图文。“知识库”新增为 `/knowledge-base`，与智能体并列，按简介、关系网络、格式化条目组织。点击关系网络中的实体可定位支持该关系的知识、条件与来源。

数据智能体把授权数据、已发布算法和知识作为不同工具检索。科研编排先展示数据输入、固定算法版本、参数及知识依据，确认后执行，持续查询计算和入库状态。任务 UUID 与输出整数 ID 分别校验，按任务入库时由服务器查找真实输出，避免要求用户寻找或猜测 outputId。

计算任务提交时的 queued 是当时的状态。对话旁的任务卡查询实时状态，并区分等待计算、等待入库、已入库、失败或授权阻断。持久化跟踪在工作进程恢复后继续，重复查询和重复入库请求复用既有记录。

## 知识组织

- 条目包含主体、关系、客体、知识陈述、解释、适用条件、例外、别名、来源、发布状态和版本。
- 当前项目知识随项目权限读取，公共已发布基础知识可在其他项目复用；公共草稿不跨项目展示。
- 发布必须具有来源标题及链接或原文定位。修改带 revision，冲突返回 409，并保存版本快照。
- 关系网络由实际知识条目派生；检索使用关键词、别名和关系匹配，并返回原始来源。当前实现没有将关键词检索称为向量检索或 GraphRAG。
- 矿物平衡核查只在矿物名称、平衡状态和体系明确时判定。条件不足返回 needs_context；发生冲突保留原观测并给出核查方向。
- 数值范围和字段要求使用内置结构化核查器，知识文本和模型输出均不作为代码执行。

首批条目依据 USGS 公开报告、开放岩矿教材和 QGIS 文档，覆盖矿物平衡、地层与构造、成矿与蚀变、遥感判读和数据质量。合同用于明确应用背景，合同全文、财务信息及联系信息未进入知识条目。

## 内容载入

使用已配置的项目运行环境，在 backend 目录运行：

```text
python manage.py migrate
python manage.py seed_geology_knowledge --dry-run
python manage.py seed_geology_knowledge
python manage.py refresh_science_column --assets <解包后的八张科普插图目录> --dry-run
python manage.py refresh_science_column --assets <解包后的八张科普插图目录>
```

地学种子只新增不存在的条目，保留人工修订。科普刷新按明确的旧 seed_key 归档旧十二篇，保留原正文与附件；八篇新版按文档顺序发布，新闻与人工文章保持。重复执行不重复添加图片。插图随发布包保存和校验，按用户约定不纳入 Git。

## 验证边界

测试中的计算和模型替身用于核对状态转换、授权、幂等和入库行为；真实模型、真实算子和服务器的验收单独记录。规则冲突提示与完整地质自动修复算法具有不同范围，合同中的查全率、查准率仍需要研究区数据与参考标注评价。

工作流界面采用持久化状态机，负责单个算法的可靠执行闭环；数据智能体可通过模型工具调用组合多个操作。编排预览本身不调用模型。首批知识检索采用关键词和别名，后续向量检索、自动 Wiki 生成与地质纠偏算子可继续在此接口上扩展。

本机验证记录：知识与科普的 12 项后端测试通过，编排与计算收尾的 51 项后端回归通过；五组相关浏览器测试共 34 项通过，导航与网络布局调整后对应 19 项复验通过。类型、构建、接口生成一致性与迁移检查通过后冻结发布；服务器验收以与提交一致的独立回执为准。
