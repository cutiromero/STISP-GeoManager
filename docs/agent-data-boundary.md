# 智能体数据发现与任务材料边界

## 普通资源发现

普通智能体的资源搜索、目录统计、目录元信息、直接编号读取、汇总、展示与手选候选使用同一个服务端可发现集合。资源必须同时属于当前单个项目、通过当前用户的资源 ACL 和功能权限、处于 `active` 状态，并完成当前类型所需的数据准备（`ready`）。管理员策略只能进一步缩小该集合。手选编号、搜索词、目录筛选和模型生成的编号不能扩大范围。

可发现的材料包括项目中的正常业务上传，以及由明确入库记录证明的用户成果。普通计算结果须来自真实成功任务和明确入库操作；工作流成果还须由完成阶段、成功计算任务、任务所有者、项目、已准备的入库记录、输出校验和及 `resultResourceIds` 交叉证明。报告须来自真实完成的工作流并核对文件指纹。`relatedResources`、`isComputeResult`、资源目录或“最终成果”名称都不能单独证明其成果资格。

已准备完成、具有独立存储的入库业务资源，不因原始计算输出的保留期届满而退出普通发现。读取原始计算输出仍遵守其过期状态与任务权限。

下列材料不进入普通资源发现，即使其编号已知、用户能在其他业务页面访问，或记录仍标为 `active`：

- `trial` 试用计算及其入库产物。
- 当前或历史任务的临时上传、字段规范化工作副本、冻结规则副本。
- 修改表、批准编辑表、检查清单和其他过程结果。
- 评价真值、参考答案和验收材料。
- 缺少真实任务、阶段或明确成果入库对应关系的工作流产物。

判断依据是资源来源、用途、任务关联和入库证据。名称中含“演示”“测试”“demo”或“test”的正常业务资料不会因此被排除；内部材料也不能通过改名进入普通候选。

普通发现集合为空时，返回真实空列表和零总数。目录列表只包含该集合中仍有资源的组别；目录筛选与关键词搜索在同一集合上执行。客户端显示空态，不回退到通用目录、全部计算输入、历史资源或其他项目。

## 当前任务材料

任务上传和内部材料通过任务专用接口使用。请求必须绑定真实的 `owner` 及当前项目，并与当前 `workflow`、上传 `batch` 或计算 `task` 的真实关联一致。请求正文、自报的资源编号或任意上下文字段不能建立这种关联。

当前批次上传可用于该批次的角色识别、字段确认和后续已绑定任务。任务内部的检查结果、工作副本和冻结规则可供该任务后续分析及审核使用；它们不会因此进入普通目录，也不能被同一用户的无关新任务自动发现。系统数据的批次引用只建立关联，不改变原资源的来源、ACL 或普通发现资格。

每次读取、恢复、续接和提交仍核对当前权限及绑定。任务曾经读取某份资料，不代表撤权后仍可继续访问。上传、字段确认、计划批准和逐项修改批准的原有确认点保持有效。

## 算法和知识

算法候选只包含算法本身 `enabled`、版本 `published` 且明确允许智能体调用的版本。手选只能缩小该候选范围；已归档、停用、未发布或未允许智能体调用的版本不能通过编号继续使用。已有任务的历史版本记录用于追溯，不成为新任务的默认可用算法。

知识使用独立的发布与领域 ACL。普通 `auto`、`manual` 和 `all` 检索只使用已发布且当前用户有权访问的知识；`manual` 进一步限定所选领域，`none` 禁用。知识不因出现在某个目录资源中而获得额外权限。草稿规则只允许在服务端明确绑定的场景及其冻结修订范围内使用，不进入普通检索或其他场景。

专用场景接口可在明确的 `scenario` 与 `rules` 角色下提供服务端注册规则。前端只在该场景规则控件中使用此授权候选，创建任务时再次核对场景、资源与知识绑定。普通角色继续使用严格业务资料集合；任意 `preset` 编号、客户端自报的角色或历史规则编号不能扩大普通数据选择器。该专用读取保留现有场景规则使用，不把注册规则公开成普通业务资料。

## 历史与新上下文

在现有历史访问授权仍通过的前提下，旧会话、工作流、证据和模型交互继续可读。历史展示与新一轮模型上下文使用不同的授权入口：过去的工具证据、内部编号、临时上传和过程结果不能仅因出现在旧消息中，就被注入无关新任务。

恢复同一真实任务时可沿其持久绑定继续；新任务重新执行当前普通发现或显式任务绑定检查。前端不把历史明细、批次上传或工作流结果合并到普通资源选择器。已失效的历史选择显示不可用状态，提交时仍由服务端重新验证。

## 正反例

| 材料或操作 | 普通资源发现 | 允许的使用范围 |
| --- | --- | --- |
| 当前项目已准备完成的业务岩性图，名称为“演示区岩性测试数据” | 允许 | 按当前 ACL 搜索、统计、手选和分析；名称中的演示、测试不改变资格 |
| 同名资料属于其他项目 | 排除 | 必须切换到其实际项目并通过权限检查 |
| 当前项目业务栅格仍在预处理中 | 排除 | 等准备完成后重新发现 |
| 普通成功计算后由用户明确入库的业务成果 | 允许 | 按成果来源、项目和 ACL 重新验证 |
| 成功工作流已登记的明确终端成果 | 允许 | 核对真实阶段、任务、终端输出和成果登记关系 |
| `trial` 入库结果改名为“正式最终成果” | 排除 | 改名不改变试用来源 |
| 本人上传到当前批次的地质图 | 排除 | 仅当前批次及其后续真实绑定任务使用 |
| 本人另一批次的临时资料，编号已知 | 排除 | 不能直接作为无关新任务的普通输入 |
| 工作流字段规范化副本、修改表或检查清单 | 排除 | 当前真实任务的分析、审批及追溯 |
| 已登记评价用途或保留评价来源的资料改变名称或目录 | 排除 | 来源与用途记录继续生效；不根据文件内容猜测未登记用途 |
| 已发布且通过领域 ACL 的地质知识 | 独立知识检索 | 由知识模式和所选领域继续收窄 |
| 已明确绑定场景的草稿试用规则 | 排除普通发现及普通知识检索 | 仅对应场景与冻结修订，不用于无关场景 |
| 旧会话中的内部工具结果 | 排除新任务自动上下文 | 原历史授权有效时可查看；续接须验证同一任务绑定 |
| 筛选后没有普通业务资料 | 空列表、总数零 | 显示空态，不借用其他目录或历史候选 |

## 接口和前端约定

`GET /api/agent/resources/` 提供普通智能体手选候选。`GET /api/agent/workflow-uploads/references/` 提供同一边界下可加入当前批次的系统数据，返回的总数及目录同时受限；`POST` 再次验证全部引用。普通发现工具与直接编号读取沿用同一集合。

`GET /api/agent/bootstrap/` 的 `algorithmOptions` 和 `knowledgeDomains` 是智能体入口的授权候选。通用计算表单的字段、波段或 manifest 只用于补齐已授权资源和算法的交集，空白名单不回退计算中心候选。专用场景规则另按服务端场景接口的明确 `rules` 授权使用。临时上传、绑定材料和历史查看继续使用各自的专用接口。

这些约束不改变响应结构，不新增绕过当前项目、ACL、任务所有者或批准流程的入口。

系统数据批次引用在同一事务中先对现有用户行执行不改变值的更新以预占数据库写锁，再重新核对权限、业务资源和批次状态。SQLite WAL 模式下，权限查询不能先于该写操作建立读取快照，否则并发会话或 worker 提交后，事务无法升级为写事务。整批引用仍原子提交；资源无权访问、批次已绑定或资料画像失败时整批回滚。
