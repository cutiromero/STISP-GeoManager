# 双 Demo 本机演示说明

本轮把两个小案例接入现有智能体、计算中心、知识库和地理工作台。访问 `http://127.0.0.1:5173/`，使用已有获授权账号。服务器部署另行安排。

## 目前可以演示什么

| 案例 | 页面能看到的过程 | 实际计算成果 |
| --- | --- | --- |
| 干旱区生态风险评估分析决策 | 两期资料核对、变化线索、调查排序、补充观测后的判断对照 | 两期 NDVI、变化栅格、候选区、调查优先区、分区统计 |
| 地质逻辑推理 | 初图检查、几何候选审核、有限属性修改、再次检查 | 原图、修正图、问题位置、逐项修改记录、质量报告 |

资料为固定种子的模拟小样例。所有算法由平台执行器真实计算；当前判断展示使用明确标注的模拟模型。模拟模型用于验证读取结果、证据绑定、后续调用及刷新恢复，真实模型判断另行验证。

公开的“分析说明与决策依据”展示发现、判断、算法依据、实际结果、引用和下一步。每步保存当前输入角色、知识修订、真实任务和产物来源；它是可核对的判断摘要。

## 生态演示

1. 切换项目到“干旱区生态风险评估分析决策”，进入智能体，打开输入框的“科研工作流”。
2. 选择“干旱区生态 · 变化与调查优先区”，分析模型选择“模拟模型”。按角色选择前期影像、后期影像、共同有效像元掩膜、调查分区、初始生态背景与观测表。名称匹配可协助选择，随后核对角色。
3. 样例日期为 2025-09-15 和 2026-09-15；红光为第 1 波段、近红外为第 2 波段。影像为 128×128、30 米网格的模拟反射率影像。
4. 知识依据可选遥感基础及干旱区生态；下降阈值默认 −0.15，最低有效覆盖率默认 0.65。生成计划，核对后确认。
5. 平台依次计算前期 NDVI、后期 NDVI、变化和调查优先级。每一步先读实际结果，再记录下一步分析说明。任务卡可打开已入库地图成果。
6. 在完成的工作流中点击“补充观测后更新判断”，把观测表换成补充观测版，其余角色和参数沿用。生成更新计划并确认。
7. 页面展示原判断、新增观测和更新判断；系统复用原变化栅格，只重新计算调查排序。地图可加载旧、新调查优先区，点击区域查看实际统计和理由。

样例初期农田区调查顺序第 1、植被下降区第 2。加入同分区、同期间的可信收获记录后，植被下降区升至第 1、农田区降至第 2。排序由下降面积占比、平均变化、缺水线索和收获解释的明示规则计算。缺资料区有效覆盖约 20%，单列“优先补资料”，没有调查排名。

这些结果描述两期植被变化及调查安排。后续可替换真实同网格影像、有效掩膜和现场观测；持续退化及原因解释结合更长时间和辅助证据。

## 地质演示

1. 切换项目到“地质逻辑推理”，进入智能体的“科研工作流”，选择“地质填图 · 检查、纠正与复核”，分析模型选择“模拟模型”。
2. 选择模拟初始填图、调查证据表、结构化检查规则表。选择地质知识分区，生成并确认计划。
3. 初次检查输出明确问题和证据不足项。几何修复形成候选结果；出现“待审核”时先查看质量报告，再确认继续。
4. 平台读取修复后的实际地图再次检查。修改计划仅针对最近检查中有证据的可修复属性；编辑算法重新核对原值、规则、证据和输入版本。
5. 输出新地图并重新检查。成果对比入口将原图与修正图一起加载；图层可切换，修改对象有主题颜色，点击查看修改字段、旧值、新值、原因和证据。

六个模拟地质面中包含一个无效几何、一个接触类型错误及一个低置信调查记录。实际流程修复几何、修改一项接触属性；最终低置信项保持原内容并标记待复核。独立参考图及设错清单只在 `acceptance-isolated` 验收目录使用，没有登记为项目资源或提供给模型、知识检索与算法。

## 刷新与重复演示

工作流历史保存在本人当前项目下。刷新页面或离开后，从历史记录打开即可恢复计划、判断摘要和原任务。重复提交同一幂等请求复用原工作流；证据更新创建关联旧分析的新工作流，保留前后记录。发起新的独立演示则生成新计划。

输出按现有权限和质量流程保存到“计算结果”资源中。自动入库只处理通过质量门的结果；几何候选需要沿用审核流程。原始资料和正确对象保留。

准备入口为 `backend/manage.py prepare_dual_demo --config config/app.test.toml`，在仓库根目录点载 `activate-local.ps1` 后用已配置项目 Python 执行。命令复用已有 Demo 对象并保留人工修订；算法源码改变时提升版本，重新试运行，通过后发布。

已登记并真实验证的算法为 NDVI、矢量几何修复、NDVI 变化、生态调查优先级、填图检查和受约束属性编辑。填图检查 1.0.0 的失败记录保留，修正版 1.0.1 已通过试运行后发布。

资料和大结果位于 TOML 配置的科研根目录，样例在 `demo-assets/dual-demo-20261010`；运行审计、对象清单和任务回执在本机 `.runtime/dual-demo-20261010`。凭据、配置、数据库、样例和大结果独立保存。

本机为两个 Demo 启用了算法调用，并将资源选择上限设为 12、多步算法预算设为 12。它们是本机策略设置，仍由后台管理，原默认资源上限保持 3。
