# 智能体怎么工作、参数怎么调

2026-09-23，依据v0.1.13代码、管理接口测试、浏览器和真实Qwen验收。

## 一次提问经过什么

网页提交问题、模型选择和快答/深度思考模式。Django检查用户、项目和功能权限，把任务存进数据库；独立agent worker读取任务及后台策略，组织系统指令、历史、当前问题和附件，通过服务器本机HTTP接口调用vLLM中的Qwen。模型产生的正文、思考及执行事件分别保存，再显示到网页。

“模型对话”主要回答问题。“数据智能体”还会按权限使用数据查询等工具，读取结果后再次询问模型，直到完成或达到步骤/时间限制。每次模型调用都重新核对完整输入长度。“算法计划预览”目前是单次计划逻辑，没有实现反复实验、评价和优化的自主科研循环；原来的最大迭代轮次属于预留项，现已标明并禁用。

Qwen3.8-27B是服务器已经部署的模型，平台通过固定模型注册配置选择它；网页不会自己下载或训练模型。模型权重、vLLM推理服务和本平台是三个部分，换平台参数不会改模型权重。本地开发使用明确标注的模拟模型。

## 两个长度有什么区别

- 总窗口：模型一次能容纳的输入与输出总量。输入包括指令、历史、附件、工具返回；输出包括思考和最终正文。
- 生成上限：单次调用最多生成多少token，是额度而非必须生成的长度。
- token是模型分词单位，不等于汉字、英文单词或字节。不同文字和符号的比例不同，平台现在用实际服务的分词接口计数。

旧32768来自vLLM启动脚本；旧4096来自平台已保存策略，通过max_tokens传给模型。4096用于普通短答经常足够，深度思考可能先耗尽预算，正文尚未来得及输出。真实候选重问本次成矿问题用了4899 token，已超出旧额度。

正式服务现为65536总窗口、16384生成上限、49152输入预算、中等思考强度。实际约束是：

`完整输入token + 16384生成预留 + 256安全余量 ≤ 65536`

因此当前完整输入最多48896 token。提高生成量会减少同一个窗口中可留给输入的空间；扩大总窗口需要调整模型服务并重新启动，网页里的输入预算本身不能扩大总窗口。更长上下文增加计算和KV缓存需求，更高输出额度允许更长生成时间，因此本次先验证并采用64K窗口。

## 后台参数到底有没有传过去

已通过管理接口保存两组不同参数，捕获模型实际HTTP请求，确认生成上限、温度、Top P、思考强度逐项一致。正式网页保存后，真实Qwen任务也记录了65536/16384/medium。回答旁显示该次调用的实际输入、输出上限和用量，方便以后核对。

后台不同参数在不同层生效：温度、Top P、生成量、思考强度传到模型；输入预算在发送前裁剪；用户范围、每日次数、并发、工具开关在平台控制；超时控制worker；模型总窗口属于部署参数。预留的迭代字段没有实际循环可控制。管理员保存后，新开始的任务采用新参数，正在运行的任务保留开始时的生成参数。

## 已修正的问题

| 现象 | 原因与现在的处理 |
| --- | --- |
| “未完成”“达到回答长度上限” | 思考与正文共用旧4096额度；提高额度并提供low/medium/xhigh思考强度，默认medium |
| “模型未返回可展示的思考内容” | 旧实现可能在截断前没有刷新未闭合的思考缓存；现流式保存并在截断时保留已有内容 |
| 字节上限很大却仍可能超窗口 | UTF-8字节无法准确换算token；现对完整请求真实分词，保留输出空间 |
| 不清楚后台修改是否生效 | 新增每次调用的实际参数及生成用量记录，并做管理接口到HTTP请求的验证 |
| 工具开关、提示语不一致 | 按策略与本次联网开关筛选工具，去除矛盾指令，保留真实权限错误提示 |
| 工作流看起来像能自动反复科研 | 页面改为算法计划预览，预留迭代字段禁用，实际运行到计算中心进行 |

已失败的历史任务保持原记录，修复不会自动重写或重新执行它们。重新提问才能验证新版本行为。达到新上限仍可能发生，届时会保留已生成内容并明确显示未完成。

## 日常怎么控制上下文

在后台管理→智能体设置中调整输入token预算、思考强度和生成上限。换研究主题时新建会话；上传与当前问题直接相关的附件，避免把大量无关材料放进同一轮。超预算时平台先移除较旧对话，再移除旧工具交互，必要时缩短附件文本，保留当前问题；仍放不下会明确报错。界面会标记发生过上下文裁剪。

普通问答可用快答；需要推理时采用中等思考。深度思考消耗的是同一份生成额度，所以4096 token绝不能直接理解为“能回答4096个汉字”。

## 新增算法

- NDWI水体指数：输入包含绿光和近红外的多波段反射率影像，选对波段，输出GeoTIFF。指数可用于辅助判别水体，具体阈值应按数据和研究区域确定。
- 矢量面积与周长：输入具有坐标系的有效面矢量，输出保留原字段的GeoPackage，新增area_m2和perimeter_m；面积扣除孔洞，周长包含孔洞边界。

计算中心先按分类排序值显示栅格、矢量、表格，同类按名称和ID稳定排序。两个算法在本地与服务器都已通过人工样例任务并发布。
