# v0.1.14：数据智能体协议及当前资源修复

用户在数据智能体选择资源9并询问“分析该文件”，运行55失败。两个模型调用分别生成30和163 token，合计193；没有达到16384生成上限，也没有真正执行工具。

第一段输出是describe_resource命令，第二段是final回答。模型启用了JSON约束和深度模式，服务直接返回JSON，没有思考结束标记。旧provider把这些内容全部当成隐式思考，因此工具解析器收到空字符串。协议重试仍走相同路径，最终报错。页面把两次调用的JSON连在思考区显示，并不代表一次调用执行了两条命令。

另一个问题是当前resource_ids只用于工具权限过滤，没有明确写进模型输入。模型沿用了旧会话中的资源6和文件大小话题，偏离了当前选择与问题。工具权限检查仍然存在，没有因此读取未授权资源。

修复内容：

- 结构化响应直接以JSON对象开头时按正文命令处理，交给已有解析器和工具权限检查；真正的独立思考字段、显式/隐式思考标记仍按原语义处理。
- 每轮输入明确标记该轮所选资源ID和问题，系统指令要求以当前选择为准；历史轮次标记各自选择，附件拼接保留当前输入。
- 协议纠正时附带实际无效响应，使模型能针对错误修正。保留原始失败记录。

验证：后端67项测试通过，包括新增5个回归用例、真实HTTP多步调用和当前资源范围检查。真实模型验收使用原会话历史与资源9，在独立数据库副本运行，只开放读取和分析工具。正式状态与冻结SHA以服务器回执为准。

本次不改变模型窗口、生成预算、算子和数据，不需要数据库迁移或重启vLLM。
