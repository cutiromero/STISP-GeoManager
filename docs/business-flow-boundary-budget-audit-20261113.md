# 业务流传输与预算排查

## 排查范围

覆盖目录与发布版本、输入准备、启动请求、父运行预算、任务级主执行、真实算子衔接、审核与人工决定、上下文等待、额度恢复、状态传输、节点记录及报告交付。以3070d27为代码基线，本地分析历史记录和运行回归，不连接关闭的服务器。

业务流继续由一个主执行智能体贯穿任务。节点承担目标、工具和审核边界，未增加节点执行子智能体；算子核心计算逻辑不变。

## 历史用量依据

只读分析716份本地JSON记录及两份本地数据库，按requestId或请求摘要去重，获得30次具有完整用量记录的真实Qwen调用。模型均为Qwen/Qwen3.8-27B，来源包含正式站保存快照、候选环境验收及本地历史运行。正式站快照仅保存7次节点末次调用，不能视为完整生产历史；本样本也不能估算线上故障率或新主循环长任务的请求次数分布。

| 指标 | 样本数 | P50 | P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| 单次输入token | 30 | 1036 | 26146 | 29606 |
| 单次生成token，包含服务计量的思考与正文 | 30 | 366 | 5266 | 11238 |

29次记录提供请求耗时，最大143.284秒。生成上限记录分别为4096、8192及16384；没有已保存请求的实际生成量达到其当次上限。11238 token对应的失败记录是JSON/正文格式错误，当次上限为16384，不能将该失败归因为token耗尽。

## 额度结论

| 配置 | 处理 | 依据 |
| --- | --- | --- |
| 单次生成默认值 | 新配置使用16384 | 覆盖已经观察到的11238 token生成需求，并保留余量 |
| 标准账号任务生成上限 | 开启任务预算后允许至多32768 | 为复杂分析提供可选余量；实际受执行、审核窗口及角色配置约束，不能声称历史已证明每个复杂任务都需要此值 |
| 输入配置上限 | 保持49152 | 已观察输入最大29606；继续优先压缩历史和按成果引用读取，不扩大文件正文输入 |
| 默认总请求字节保护 | 保持384000 | 与实际token检查共同生效；组合证据不再额外套用较低的96 KiB限制 |
| 证据索引项数 | 上限512 | 允许更多小引用，仍受完整请求token与字节预算约束 |
| 单个工具观察 | 保持96 KiB | 约束一次工具返回和私有存储，不代表整次模型请求的总证据上限 |
| 单次请求时限 | 保持600秒默认值 | 已保存耗时未显示提高时限的必要，复杂档位仍需正式模型实测 |
| 任务平台模型请求保护 | 保持256次 | 没有新主循环正式长任务样本支持继续扩大；不足时保留结果，支持在允许额度提高后继续 |
| 任务算子默认次数 | 新配置由8次提高到16次 | 5次科学计算与最多7份初始资料准备合计12次，再留4次余量；依据流程结构，不能当成历史用量结论 |

上述默认值影响新建配置。已经保存的显式策略不被自动改写，正式服务恢复后需核对实际策略。提高输出上限不会要求模型每次生成更多内容，也不会扩大科学算子权限。32K生成档位的真实延迟和成功率仍须正式模型验证。

输入49152和字节384000是未选择任务预算时的默认值。已授权任务预算沿用既有服务的角色窗口、生成预留与字节保护计算，本次输入可因此不同；真实发送仍按服务窗口和分词结果检查。输入、输出共享窗口，提高生成预留时界面同步展示减少后的可用输入。

## 修复与边界

| 链路 | 问题或核对点 | 处理 |
| --- | --- | --- |
| 启动界面到API | 业务流未接入现有任务预算，复杂任务无法在入口选择额度 | 复用预算控件，传递budgetProfile及可选maxOutputTokens，进入同一角色额度校验 |
| API到父运行 | 预算选择需要与执行和审核共用 | 保存到父AgentRun，纳入幂等请求身份；会话工具启动继承父预算并检查当前权限 |
| 不同角色模型 | 较小审核模型可能容纳不了执行者所选预算 | 目录启动按执行及所有已配置审核模型的较小可见窗口解析；真实请求仍核实实际服务能力 |
| 预算展示 | 总窗口被标为可用输入，未扣除生成预留 | 分别显示总窗口和实际输入预算，明确单次请求时限；预算方案不改变明确选择的思考档位 |
| 资料衔接响应 | 切换任务后，旧补充说明请求的错误可能隐藏新任务；忙碌状态可能残留 | 使用任务代次隔离结果、错误和清理回调，重置新任务状态，阻止重复提交 |
| 节点记录 | 已加载的旧任务思考可能在新任务加载期间继续显示 | 请求结果绑定任务与节点身份，切换后立即隐藏旧内容 |
| 节点内多轮调用 | 节点状态不变时，新工具动作的模型记录未自动刷新 | 在工具交付边界更新，思考增量不触发整份记录重读；主执行记录随当前目标和工具进展更新 |
| 撤权显示 | 记录读取明确拒绝后，缓存的实时思考预览可能继续显示 | 明确撤权后同时隐藏已保存记录和实时预览，重新授权成功后再恢复显示 |
| 运行响应 | 格式正确的其他任务响应可能被客户端接受 | 运行读取与控制响应核对目标运行ID，启动响应核对流程与版本 |
| 嵌套响应 | 部分专业预算等待缺少evidence，界面直接遍历可能报错 | 后端补齐公开恢复结构，未知token数省略；前端校验恢复清单和模型记录的必需结构 |
| 专业最终节点 | 内部final_analysis及独立finalStage没有完整映射到图中的finish，等待状态可能丢失 | 统一最终节点映射，传递实际等待原因及操作，不制造额外人工批准 |
| 主执行断点恢复 | 当前判断完成后新增任务记忆，使同一响应的恢复校验误判变化 | 沿用该次请求已保存的短任务前缀；实际科学输入、目标与权限仍重新核对，避免重复请求 |
| 审核格式失败 | 连续无正文或非法JSON会终止整个任务 | 保留已有执行结果，等待显式重试该次审核，不重跑已完成计算、不代替审核通过 |
| 专业恢复控件 | 界面提供后端禁止的缩减样本和跳过证据操作 | 专业流程只显示支持的操作，保留完整科学事实及批准范围 |
| 调用额度等待 | 请求次数不足被显示成输入过长，缩减输入不能解决 | 传递等待类型和额度来源，显示真实调用用量；节点合同额度不被任务额度覆盖 |
| 进度投影 | 执行前的输入等待被计为执行完成 | 以实际执行状态计量，等待本身不增加已完成进度 |
| 额度恢复 | 管理员提高允许额度后，仍只能放弃旧任务 | 允许在原任务显式继续，保存调整记录，不清零请求计数，不代替审批 |
| 额度诊断 | 专业阶段的已用请求数没有合并工具与独立审核请求 | 统一报告任务累计真实请求数，与准入计数一致 |
| 已知最低资源 | 任务可在正常路径必定不足时启动，随后中断 | 创建前计算已知模型与算子最低需求，计入初始转换、脚本及其审核；不足直接说明需求，避免产生半程任务 |
| 算子额度续跑 | 额度耗尽变成普通工具错误，且可能提前消耗补救次数与方案签名 | 先核对额度再登记补救，等待期间保存待执行动作；提高实际任务额度后继续同一动作，不重复调用模型 |
| 初始输入恢复 | 资料准备尚无科学阶段时，恢复查找阶段可能抛异常或误改执行阶段 | 支持无科学阶段的inputs等待，恢复原phase，保留计数且不批准资料或科研结果 |
| 平台故障人工恢复 | 平台恢复后旧故障标记仍禁止原动作 | 自动重试继续禁止；明确人工恢复后清除当前阻断诊断，保留历史与用量，允许新预检和执行 |
| 节点既有配置 | 主执行者看不到冻结算子版本、参数与输入绑定，执行依赖猜测 | 提供短精确预览与只读配置引用，长内容按需片段读取；固定参数可原样复述但不能改值 |
| 成果归属 | 上游计算输出可能被当成本节点完成证据 | 非分析成果须出自本节点真实计算，固定计算节点不能仅以分析跳过实际计算 |
| 替换输入后的撤权 | 仅核验当前输入可能遗漏任务已使用的旧来源 | 当前版本来源与任务来源ID合并成一次批量ACL，实时模型边界使用同一集合 |
| 上下文投影 | 固定100项及96 KiB组合证据限制可能先于实际配置阻断 | 使用512项索引和配置的总字节边界，保留完整事实、实际分词和压缩审计 |
| 真实计算与报告 | 新预算及状态修复不得改变科研含义或批准记录 | 继续使用原算子、输入授权、质量门禁及报告中已接受的主执行分析 |
