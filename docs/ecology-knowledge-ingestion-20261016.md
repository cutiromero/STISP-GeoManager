## 导入与恢复

新增 `import_ecology_knowledge`，复用已有条目校验、项目权限、知识修订、审计、资料上传、文档去重及 WeKnora/Wiki 索引能力，没有新增 API 或数据库字段。

```text
python manage.py import_ecology_knowledge --bundle <独立资料目录>/ecology-reviewed-20261016.json --project-code demo-arid-ecology --user-id <有效维护账号> --dry-run --with-documents
python manage.py import_ecology_knowledge --bundle <独立资料目录>/ecology-reviewed-20261016.json --project-code demo-arid-ecology --user-id <有效维护账号> --with-documents
```

命令核对项目代码、真实成员资格与知识维护权限，先校验整包及来源文件摘要，再在事务中更新条目。同批稳定键幂等；同对象、同适用条件的知识合并来源并保留修订，不同条件另存。来源及条件重排不会产生额外条目。发布的条目均为 `ruleKind=none`，作为解释证据使用。

条目事务完成后才提交文档索引。文档按内容摘要去重，失败状态保存在原资料记录中，下次执行可重试；回执明确列出各文档状态，不把“已提交索引”当作“索引完成”。不持有数据库事务等待外部服务。

外部包包含：六条知识、三份审核来源摘要、原始 Markdown 与审核意见归档、来源文件摘要清单。原论文与官方 PDF 缓存在审核目录，由原 URL 和具体章节/页码回查。归档内容不作为默认检索材料上传。

## 页面与验证口径

项目选择“干旱区生态风险评估分析决策”，进入“知识库”并选择“干旱区生态安全治理”，可检索 `ECO-K001`、`ECO-K005`、`ECO-K006`、`NDVI`、`胡杨` 等关键词；条目打开后可见来源与适用条件。文档资料页提供三份审核来源摘要，自动 Wiki 进度沿用现有页面。普通智能体选择该知识分区后可调用既有知识检索工具。

自动化测试验证预演不写入、重复导入、真实文件提取路径、修订保存、同条件合并、不同范围分别存储、项目/角色权限、资料路径及摘要校验、索引失败重试。测试中上游知识服务使用模拟对象；实际模型、真实索引服务及 NDVI 任务另在候选和正式环境验证并记录回执。

建议真实模型验证三个问题：

1. “这片地两期 NDVI 下降，能否认定土地退化？请先检索本项目知识，区分当前能支持的判断、缺少的证据和下一步核查。”
2. “新疆天然草地 NDVI 下降能否都归因于干旱？请查询相关知识，说明区域、草地类型和时间尺度的影响。”
3. “塔里木河下游胡杨河岸林 NDVI 下降，目前没有地下水、树龄和输水时序资料。请检索知识，说明还需要核查什么，哪些结论暂不能形成。”

验收时核对当次工具记录、知识修订和真实引用；静态检索测试与真实模型推理分开报告。沿用现有 NDVI 任务进行计算—读取结果—知识解释时，报告需引用实际计算统计，不能预设当前项目已具有地下水、降雨或树龄观测。
