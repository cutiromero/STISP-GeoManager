# 时空监测工作区

## 操作路线

1. 在“数据目录”的资料详情中维护“监测用途与时相”：按场景选择原始输入、解译成果、标准参考或辅助资料，填写资料集合及实际观测时段。
2. 在大屏选择资料集合和时相。互花米草按方法要求选三时相组合；野火选择原始容器、监测内容、年份和实际观测时期。
3. 打开原始图层，定位原图，在地图上依次点击矩形两个对角绘制研究区；也可使用当前视野。经纬度边界可在展开区中调整。
4. 开始任务，核对本次资料、日期和范围后启动业务流。野火回看期数放在序列设置中，默认12期；FCCI按月计算。
5. 在成果时间轴切换已完成的解译，或播放已有时序。成果图层与原始图层独立开关，原始图层可调整透明度。时间未登记的成果单列，生成时间保留在成果说明中。

## 资料与时间

资料用途独立于原件和计算产物的来源标记。人工上传的历史解译图属于成果资料，不能因为它不是平台计算产物就自动归为模型输入。用途维护不改变原始文件、备份或来源。

月精度存储月初至月末，年精度存储年初至年末；日精度使用同一日期，时段精度保存真实起止日期。原生时空容器的时间点和产品有效性从时间坐标及有效掩膜建立索引。目录与年份查询只访问数据库，不扫描时空像元。

资料集合用于区分不同监测系列。栅格组合还需满足已发布方法的波段数、类型、坐标网格与时间顺序；同一期多个登记版本优先采用最新登记，原件保留。每页最多200项资料，可以切换集合或翻页；原生时期按真实年份分页，不以966期为上限。

现有RF保留三个输入位置及48特征顺序。输入日期按本次所选资料固定到计算快照，新增月份和年份不需要改代码。当前权重来自三季节训练资料，新增时相的效果需要结合相应核查资料评价；数据日期变化不代表模型已重新训练。

## 地图与计算

普通栅格通过既有后台符号化及XYZ瓦片显示。巨幅无概览输入先构建独立显示包装及降采样概览，原生网格和像元保持一致。显示包装不替代计算输入，计算仍按原件的研究区窗口读取。

野火原始图层通过共用栅格队列生成单期预览，保留有效掩膜和物理单位。预览使用对数显示拉伸、正值着色、零值及缺测透明，显示变换不进入观测统计。FCCI使用月内重复记录的均值。显示缓存限制为64幅，重复的同源同日期请求复用准备任务。

预览、任务读取及图像下载均重新校验当前项目、成员、资料用途、访问权限与资料修订。任务取消或切换来源后，页面中止等待；已销毁地图不再添加或删除图层。原始预览属于派生缓存，不登记为新的原始输入。

业务流沿用同一主执行记录、算子预检、输入版本、计算队列和标准入库。计算产物登记为成果用途，并关联观测时段。已有成果清单保持不可覆盖；展示时可依据已登记原始时相补充时间，不使用创建时间替代观测时间。

## 维护接口

- `GET/PATCH /api/catalog/resources/{resourceId}/observation-metadata/`：用途、集合、时间及来源结构。
- `GET /api/catalog/observation-metadata/?ids=...`：批量元信息，每次最多100项。
- `GET /api/ecology/monitoring/sources/?scene=...`：可用原始资料、当前方法和时相组合。
- `GET /api/ecology/monitoring/source-times/?scene=wildfire&resourceId=...&year=...`：真实观测时期。
- `POST /api/ecology/monitoring/source-preview/`：准备原生单期图层；后续使用返回的任务编号查询状态和读取图像。

全部接口显式传入当前项目。资料维护由资料维护者的编辑权限或管理员权限控制；普通查看者可以浏览其获授权资料。

批量维护可使用 `manage.py set_monitoring_metadata --project <项目编码> --actor <维护账号> --resource <资料编号> --metadata-json '<元信息JSON>'`。原生容器登记时自动建立实际时间索引。算子通过 `register_spartina` 或 `register_wildfire` 的 operator、trial、publish 三阶段登记，试运行显式提供原始资料和参数。
