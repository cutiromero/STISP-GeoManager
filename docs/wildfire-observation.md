# 野火历史观测业务流与大屏

## 数据与执行范围

项目“陆地生态系统风险评估预警”保存SeasFire v0.4原生Zarr数据，资源1475；变量目录1476、时间索引1477、气候指标及有效掩膜1478。原生容器保留59个数据变量、720×1440的0.25度格网和2001–2021年966个真实时间点。

“野火历史观测制图”从该容器读取实际观测，生成物理量图、分级图、区域统计和历史序列。五份U-Net++权重已完成严格加载、预处理方案与实际观测对比；方法和指标见[野火权重与预处理方案对比](wildfire-model-assessment.md)。模型试算保持独立的方法版本和性质。

| 产品 | 数值单位 | 时间处理 |
| --- | --- | --- |
| GWIS火烧面积 | ha | 原始周期，依据有效掩膜，2002–2021 |
| GFED火烧面积 | ha | 原始周期，依据有效掩膜，至2015 |
| FCCI火烧面积 | ha | 月内重复记录取月平均，至2020 |
| CAMS火辐射功率密度 | W m-2 | 原始周期，有效格网均值 |

原始时间轴每年46期，年末周期为5或6天，其余通常为8天。显示日期来自原始坐标及已登记索引，不插值补齐。FCCI为月度数据在月内多个时间点重复，不能将重复值累加为月或年火烧面积。面积已经是ha，区域统计直接按格网观测值求和，不乘显示像元面积。

## 业务流

1. 在陆地生态系统风险评估预警项目打开「野火历史观测制图」。绑定资料管理员已登记的 SeasFire 原生 Zarr 立方体。立方体须含经纬度、真实时间坐标、变量和产品有效掩膜；普通 TIFF、火点表和模型权重不能替代该输入。
2. 选择实际变量和观测期：GWIS、GFED、FCCI 提供火烧面积，单位 ha；CAMS 提供火辐射功率密度，单位 W/m²。FCCI 按月平均，其余采用原始观测窗口。趋势范围默认当前期，可按真实时间选择受预算约束的多期统计。
3. 启动后按资料全域执行已发布 `wildfire-observe` 算子。主 Agent 核对资料、观测范围、已确认时段和实际输出；日期到实际索引由平台转换，不需再次框选。

原始Zarr按[966,180,360]组织时空分块，一块解码约250MB。适配一次读取所需的连续时段，避免逐期重复解压。输入版本绑定原始元信息、坐标、产品有效掩膜及选中分块的物理身份，以及产品、时期集合和研究区；变化后拒绝旧输入复用。读取、执行、恢复和入库均重新检查当前权限，不以裸服务器路径替代资源授权。

| 交付 | 内容 |
| --- | --- |
| 观测原值图 | 真实时间及原单位，Float32，零观测与缺测分开 |
| 观测值分级图 | 明确物理量区间及暖色图例，不称为风险等级 |
| 区域统计 | 火烧面积求和或FRP有效均值，有效/正值格网计数 |
| 真实序列表 | 实际开始、结束、单位、观测汇总，缺失期为null |

FCCI按月平均后形成月序列。没有有效观测时返回具体日期或区域缺口，保留已完成成果，不生成模拟曲线或补造零值。

## 大屏展示

在数据中心的任务分组查看原值图、分级图、统计与观测序列。核对单位和日期后，将原值图登记为正式主地图。大屏按区域和产品口径展示最新观测及关键实测统计，不解释为未来着火概率、风险等级或实时预警。分级图和序列表仍保留在同一任务。

## 现有正式观测案例

2019-12-27至2019-12-31、112°E–154°E及44°S–10°S研究区的GWIS观测，原始汇总为772,742.372559411ha，307个正观测格网。原值资源1479、面积分级资源1480，监测产品10和11。它们通过已有标准导入和管理员观测登记接入，原生资源1475–1478保持不变。

正式站gongxt浏览器已核验原值/分级实际数据集497/498、暖色格网与图例、真实时段、面积汇总，四种窗口及全屏通过。此案例属于历史观测资料；新业务流及专用页面的程序发布以独立候选验收和标准发布回执为准。

## 发布与模型接入

使用register_wildfire的operator、trial、publish阶段维护私有业务流，沿用公共的不可覆盖版本与真实试运行门禁。联合候选验证使用tools/monitoring/scientific_candidate_check.py，仅在隔离候选中复制所需原始分块子集和索引，不复制完整立方体或备份整套科研数据。

模型试算采用11变量、有效值标准化、缺测填−1和原值陆海掩膜的重建方案。独立推理环境复用既有PyTorch，补齐segmentation-models-pytorch及缺失依赖；既有平台环境保持原样。w1/w2/w4/w8/w16的目标期映射尚未唯一确定，风险业务流需要结合目标期、区域验证和概率校准另行登记方法版本。

五份checkpoint已使用服务器现有PyTorch的`weights_only=True`及内存映射逐份检查，均保存986个状态项，输入卷积形状为48×11×3×3；训练记录为epoch 49、global_step 36850、Lightning 2.6.1。文件没有`hyper_parameters`或输入归一化配置。源码中的11变量列表属于ClimaFire定义，U-Net++类本身没有变量名到通道的映射，接入U-Net++前还需确认实际训练顺序。
