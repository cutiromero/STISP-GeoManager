# 互花米草与野火遥感监测接入

## 数据与模型依据

资料来自实验服务器两个原始目录与 ChinaEurope PostgreSQL 的只读查询。两个目录共 1,966 个文件，128,134,614,311 字节；互花米草 26 个、35.27 GB，野火 1,940 个、92.86 GB。迁移总包为 49,827,809,380 字节，包含完整路径、逐文件 SHA-256 与独立恢复工具。数据传输、恢复验收和模型可用性是三个独立状态。

| 场景 | 已核实的资料 | 适合的展示 |
| --- | --- | --- |
| 互花米草历史分布 | `UNet_互花米草.shp`，12,881 个面，EPSG:4326，字段 `value`；缺少独立的获取时间与精度报告 | 沿海分布面、区域定位、斑块数量、经地表面积算法计算的面积、来源和质量说明 |
| 互花米草 UNet | 单通道输入 `x.tif`、`best_model.pth`、PyQt 推理代码、归一化与后处理配置 | 研究区影像→概率与分类→斑块→核验→成果；需先确认单通道物理含义与训练预处理 |
| 互花米草随机森林 | 2025 年 3、8、12 月，每月 16 波段，三幅同网格影像；一个 RF 权重与 PyQt 推理代码 | 三个季节作为一组 48 维特征形成一次识别；波段顺序和月份顺序必须冻结 |
| 野火历史数据 | SeasFire v0.4 Zarr，EPSG:4326，720×1440、0.25°、966 个时间片；坐标实读为 2001-01-01 至 2021-12-27 | 历史时空回放、气候与植被驱动因子、烧毁面积和火辐射功率；每年46个周期，跨年末期长度不同 |
| 野火模型 | 5 个 `unet_w1/w2/w4/w8/w16.ckpt`，`UnetPlusPlus`、EfficientNet-B5、11 输入通道 | 区域野火风险概率、阈值与有效区域、权重对照、历史回报；预测有效时间必须另有依据 |

`merged_202012.tif` 实际为三波段 Byte RGB，不作为互花米草分类掩膜。三个月份 RF 输入是一个分类任务的季节特征，不直接形成三次独立的面积观测。UNet 分布面没有可靠时间字段，页面显示“时间待核实”，不能从文件名或修改时间补造观测时间。

三幅 RF 影像均为 150,793×202,865×16 Float32，覆盖同一网格。压缩文件大小不反映解码内存。UNet 输入为 150,185×194,617×1 Float32。生产推理必须先裁研究区，再按有效块读写；概率融合、分类、面积统计与矢量化都不能创建整幅内存数组。

互花米草UNet权重实读的首层为`[64, 1, 3, 3]`，输出层为`[1, 64, 1, 1]`，与单通道二分类代码一致。RF文件的有限pickle元信息扫描读到`n_features_in_=48`和`_sklearn_version=1.7.2`，没有执行反序列化；运行环境需核对该版本、joblib及`classes_`，不能默认使用任意新版scikit-learn。

野火的固定通道顺序为 `mslp, tp, vpd, sst, t2m_mean, ssrd, swvl1, lst_day, ndvi, pop_dens, lsm`。现有 `inference.py` 只用随机张量验证输出形状，没有读取 Zarr、恢复训练归一化、处理 NoData、应用 sigmoid 或写地理输出。文件名 `w1/w2/w4/w8/w16` 和库中“回看窗口”的声明不能证明预报时效；正式接入前须核对训练切分、目标定义与检查点。模型 logits 不直接当概率，未经校准的概率不等于置信度或精度。

源库登记的野火 11 波段 GeoTIFF 接口与当前目录的 Zarr 需要输入适配。旧 `/nfs` 路径、镜像名称与模型目录只是登记信息，不证明原服务或原文件仍可访问。库中“互花米草识别”“次季节预警”“极端野火预警”的描述不用于替代实际代码与权重验证。

完整立方体使用野火原目录下的 `wildfire/seasfire_v0.4.zarr`，其与上一级完整数据组为逐文件哈希一致的两份路径。`climafire-demo/seasfire_v0.4.zarr` 只是部分数据，虽有完整 `.zmetadata`，却缺少 `time/0`、`latitude/0`、`longitude/0` 坐标块；直接打开会得到填充值，不能作为正式输入。完整副本坐标实读为经度 -179.875 至 179.875、纬度 89.875 至 -89.875，纬度递减。

五个野火检查点均已用 `weights_only=True`、`mmap=True` 只读检查，输入卷积权重形状为 `[48, 11, 3, 3]`，输出头为 `[1, 16, 3, 3]`，与提供的11通道 UNet++相符；没有保存 `hyper_parameters`。这些结果不能补足训练归一化、目标期或窗口语义。

源库互花米草记录包含2020与2025两年的三季节影像目录，但本次文件包只有2025三季节预测输入。野火目录还登记4,740份风险结果与28份2026年11通道输入；对应旧`/nfs`原像素未确认可读，不能承诺这些年份已经可在大屏回放。

## 两条业务流的展示路线

业务流沿用统一主执行智能体、计算中心、输入预检、受控结果入库与不可覆盖版本。大屏消费已入库成果，不承担计算调度。以下是场景蓝图；待业务流核心优化完成且科学输入明确后，再冻结具体算子版本并发布可执行业务流。

### 互花米草识别与变化核查

1. **选区和资料确认**：选择沿海研究区、识别路线、观察周期，核对影像 CRS、网格、季节、波段、NoData 和模型版本。RF 明确需要三季节完整组合；UNet 明确单通道含义与训练预处理。
2. **影像准备**：只读原件；裁区、有效区掩膜、网格检查，生成受控输入。三月份 RF 影像不被解释成三次监测成果。
3. **分块模型识别**：选择经验证的 RF 或 UNet 算子，保存权重摘要、参数、随机种子、执行日志与结果引用。
4. **斑块与统计**：概率图、分类图、斑块边界；面积按合适投影或椭球面积计算，剔除无效区，记录面积单位与统计范围。阈值敏感区与模型分歧单独表达。
5. **变化与核验**：只有时间、有效范围、类别、模型和处理口径可比时计算新增、消退、稳定面积；否则仅作分布成果浏览。没有验证样本就不报准确率。
6. **成果与大屏**：复用入库门禁，登记地图资源、统计与来源。人工复核状态清楚显示，生成可追溯报告。

推荐演示顺序：全国沿海总览→一个有有效数据的典型湾区→影像与分布面叠加→斑块与面积→模型和来源→启动研究区识别。历史成果可先独立使用；多期变化与模型对照在有可比成果后开启。

### 野火历史回报与区域风险研判

1. **日期、区域与目标确认**：选择实际存在的时间片、研究区、权重；区分观测区间、输入截至时间、生成时间和预测有效区间。
2. **Zarr 输入准备**：按实际坐标读取必要变量和时间片，保持固定通道、单位、经纬度方向与训练标准化。8 天周期末端跨年长度以真实坐标为准，禁止用固定间隔外推全部日期。
3. **模型风险推理**：严格恢复匹配权重，输出 logits 后按模型目标生成概率；陆地与有效数据范围掩膜，阈值显式记录。回看步数和预测提前天数分别登记，未知时效留空。
4. **区域汇总**：阈值以上的有效陆地区域面积、有效覆盖率、区域概率统计；0.25°结果不放大成精确着火点。未知、海洋和缺测不按零风险处理。
5. **历史验证与解释**：用目标期真实观测做回报分析。区分 GWIS 烧毁面积 `ha`、FRP `W m-2` 与预测概率；驱动因子关联不直接宣称因果。
6. **成果与大屏**：提交风险图、观测图、统计、模型及时间依据；未核实预测时效时只允许展示历史分析，不能发布带伪造有效期的预警。

推荐演示顺序：全球/中国历史场景→选择 8 天周期→风险与历史观测切换→区域统计→驱动因子→权重及适用范围。没有接入实时观测或预报驱动数据时，页面保持“历史数据/模型结果”语义。

## 监测大屏

沿用 `/results/ecology-monitor`、项目功能 `ecology_monitor`、独立深色地图界面与当前项目权限。胡杨演示保留原来的模拟标签；互花米草和野火作为独立场景使用真实资源与明确的空状态，不生成站点、风险、趋势或预警来填空。

| 位置 | 互花米草 | 野火 |
| --- | --- | --- |
| 顶部 | 场景、成果时间、历史/模型/待复核标签 | 场景、输入/观测时间、权重、已核实的有效区间 |
| 中央地图 | 分布面/分类与概率瓦片，研究区定位 | 后端渲染的风险/观测瓦片，真实网格精度 |
| 左侧 | 成果列表、时期、统计范围 | 实际时间片、观测与模型产品、权重 |
| 右侧 | 面积、斑块数、质量与来源 | 有效区统计、阈值、覆盖、模型与时间依据 |
| 下方 | 业务路线、资料/模型准备状态、进入业务流 | 业务路线、资料/模型准备状态、进入业务流 |

首期采用手动刷新和成果选择，不用定时器假装数据持续更新。无成果时显示接入所需的资料和步骤；数值缺失显示“—”，零只表示经过统计的真实零。大屏选择产品后才请求现有资源 profile 和瓦片，切换场景/项目取消旧请求。浏览器只加载地图数据，不解码原始科学栅格。

## 产品交接

复用 `ecology.RemoteSensingProduct`，通过 `data_resource` 绑定已入库地图资源，以 `metadata.monitoring` 保存结构化交接信息。产品编码在同一项目内稳定，重登记相同内容幂等，内容变化使用新编码；不覆盖已发布成果。

每份产品必须包含场景、产品性质、质量状态、来源说明、局限、源资源 ID、模型与参数依据、统计范围及地图资源。可以缺少观测时间，但必须保留空值和说明。模型结果必须声明权重 SHA-256 与版本；野火预报若提供有效区间，必须同时提供输入截至时间、提前天数及目标定义的证据。历史分布导入可以先没有模型权重和业务流 ID，不冒充新计算。

统计项只接收有限数值与明确单位。面积单位使用 `ha` 或 `km²`，概率在 0–1；`null` 表示未计算。空间数据、统计及其全部来源资源必须同属当前项目，且读者对所有资源都有访问权。资源停用或撤权后，相关产品和汇总不再返回；不通过大屏泄露私有来源的派生统计。

`GET /api/ecology/monitoring/` 返回当前项目已配置场景及可见产品，只读元信息，不打开 Zarr/TIFF、不计算面积、不运行模型。产品地图使用现有 catalog/raster profile 和瓦片接口，再次执行资源权限检查。登记命令只登记已入库资源，不把外部服务器路径交给浏览器或绕过标准导入。

## 传输完成后的接入顺序

1. 复用迁移端完整回执与逐文件 SHA-256；`.part`、分段和仅完成的归档不视为可用资料。原件仍留在独立科研数据根，不重复复制整套数据或模型。
2. 用准备检查读取影像头、Zarr 元数据和代码摘要，区分文件齐全、语义明确、依赖就绪和算子验证。检查缺项形成可处理清单，不能自动安装到 `gxt` 或平台环境。
3. 先按标准矢量导入接入已有 UNet 分布面，保留时间待核实和未验证精度；按检查清单注册大屏产品。
4. 在隔离的模型计算环境中完成小研究区试运行与科学一致性验证，再登记不可覆盖的 RF/UNet、Zarr 适配和野火推理算子版本。`gxt` 当前缺少 rasterio、scikit-learn、xarray、Zarr、Lightning、SMP 等必需依赖，依赖变更需单独确认。
5. 基于统一业务流构建规则完成两条业务流，绑定真实输入、算子与成果合同；用真实任务输出接入同一大屏产品协议。

本方案的可用边界是“现有成果可展示、真实输入可预检、模型执行条件透明”。缺失的训练预处理、标签/目标定义与时效说明需要资料提供者补充，不能靠试跑输出形状代替科学验证。
