# 通用地质推理工作流（geology_generic）

日期：2026-11-03。适用范围：核地院逻辑推理项目的 MH-workflow。

## 目标

用户上传自己的资料，在不预先整理字段名的情况下完成岩性、构造、蚀变检查及远景区比较。资料只属于本次任务，不进入项目数据目录。只要求地质图中能识别出地层或填图单元名称，其他字段由智能体理解，用户确认后生效。

## 系统数据与最终成果（v0.1.58）

对话输入区“选择系统数据”搜索当前逻辑推理项目中本人有权访问的活动矢量、栅格、表格；可多选，与上传资料合计最多12份。每条资料标明“系统数据”或“上传资料”，统一参与角色识别、角色核对、字段确认、工作副本和独立评价。移除目录条目仅解除引用；原数据及其来源、隐私、状态、存储不变，可被其他批次和任务继续引用。批次发送或绑定任务后保留依据，不再允许移除。

目录资源画像读取既有存储：矢量为平台GeoPackage图层；表格使用目录的SQLite或文件读取器；栅格读取与算子冻结一致的源数据，检查真实CRS和单波段。显示COG可能重投影或增加alpha波段，不能作为计算波段数。源数据缺失、尚未处理完成或无权访问时拒绝引用，不临时复制或降级使用显示影像。

综合推理算子版本为 **1.0.5**，全部保持 deterministic。获批 `reclassify` 并入共享边界最长的相邻目标单元，编号及地质属性保留宿主；`set_code` 后存在相邻同单元时也融合。点接触或有间隙不融合；未批准的其他对象不变。L-05仍严格绑定已批准的实测宿主。几何有效性及总覆盖范围在输出前复核。

重分类和代号修正以获批的目标单元代号寻找宿主，不以待修正对象的旧分类字段或颜色作为阻止融合的条件。未提供构造时，下游显式使用已登记的空构造工作副本，不要求生成不存在的构造输出。

成果登记清单：

| 成果 | 输出键 | 字段与用途 |
| --- | --- | --- |
| 修正后岩性图 | `lithology` | `feature_id`、名称、代号、单元等原有地质字段及置信度；不带处理状态、规则或样式字段 |
| 修正后构造图 | `final_faults` | `line_id`及原有地质字段；获批剔除的线删除，不带状态、权重 |
| 有效蚀变 | `final_alterations` | `feature_id,alt`；仅包含参与推理的图斑 |
| 修正前/后远景区 | `before_zones,after_zones` | `zone_id,grade,area_km2`；A/B类多边形 |
| 修正记录（按要素分层） | `changes_lithology_issues,changes_fault_issues,changes_alteration_issues` | 修改前几何、要素类型、原编号、实际动作、原/新代号、宿主编号、被并入编号、规则、批准理由；统一橙色 |
| 问题清单/处置记录/远景区依据 | `issues,changes,evidence` | 分别保存完整问题、执行记录和逐区证据链，不污染最终图层 |

空矢量成果不登记伪要素；全部剔除时显示空图，不能回退到原图或计算状态图。`faults,alterations`旧键继续保存完整计算状态和权重，供recheck、relations、prospect使用，登记为隐藏任务工作资料，不进入成果列表、目录、地图展示或报告交付清单。降权仅影响计算输入，展示图仍保留该要素。对比与讲解读取干净成果；岩性按单元名称配色，修正记录独立展示。最终岩性默认边线保持普通细线，不依据修改状态描边；地图自身的选中高亮不属于结果数据。

双图讲解中的橙色虚线来自独立的修正记录叠加，并非最终岩性几何或字段；默认关闭，勾选“修正记录”后显示。点击要素或进入单处导览时的定位高亮也不写入成果。

## 用户流程

1. 在逻辑推理项目（项目编码`02`、`demo-geology-reasoning`）进入智能体，新建对话。点击输入区“上传资料并开始逻辑推理”，用一句话描述目标，不打开独立任务抽屉。
2. 一次拖入多个文件或含子目录的总ZIP：Shapefile组成文件、GeoPackage、GeoJSON、GeoTIFF、CSV 或 Excel。同名Shapefile组件合为一份，最多12份资料。逐份展示错误，成功资料保留；上传期间禁止发送并显示正在读取资料，上传后提示输入要求并发送。
3. 发送后批次关联当前对话的研究任务。对话卡片展示每份资料的角色建议与依据，默认填入可修改的建议。点击“继续分析”明确确认全部角色，或直接回复“把第3份资料改为构造线”修改建议后再回复“确认资料角色”；角色修改不自动创建或执行工作流。
4. 角色确认后创建真实`AgentWorkflow`并绑定上传批次。智能体判断字段含义，在对话中展示“确认字段含义”卡片，用户改正后确认，也可回复“确认字段含义”采用当前建议；必需字段缺失时不能继续。
5. 平台生成工作副本，在当前对话展示待确认计划。点击“确认执行”或回复“确认计划”后才能调用算子，不把上传或角色确认当作计划批准。
6. 检查建议在对话中逐项批准，未选中和待裁定项保留。“只批准岩性类建议”只选择当前建议中的岩性对象，沿用原有计划哈希、版本和动作校验。不能精确识别的回复返回提示并保留卡片，不交给模型推断批准。
7. 执行、复查、远景区和报告沿用真实工作流记录，在对话中展示进度与成果；完成后可展开过程及报告，点击“在地理工作台对比成果图层”在新标签查看。没有提供足够可选资料时，仍按分段规则执行，不承诺生成不存在的构造或蚀变成果。
8. 左侧历史对话即任务历史。重开会话恢复角色建议、字段/计划/批准状态及同一工作流的成果，不依赖浏览器存储还原任务。发送前尚未关联对话的上传草稿不承诺刷新恢复。

人工确认阶段先读取轻量card，再读取一次full展示当前控件并停止定时轮询；确认后继续轮询。运行中每轮读取card，仅状态变化时补读研究运行；已完成会话只读一次card，展开后才取完整过程。角色识别随发送后的研究处理进行，输入区不重复识别，也不为全新随机批次请求空列表。其他项目与已有演示场景保持原入口。

## 资料角色

| 角色 | 类型 | 是否必需 | 字段含义 |
| --- | --- | --- | --- |
| `lithology` 地质图 | 矢量面 | 必需 | `name` 地层或填图单元名称（必需）、`geo_sym` 代号、`conf` 分类置信度 |
| `faults` 构造线 | 矢量线 | 可选 | 只用几何 |
| `coverage` 研究区范围 | 矢量面 | 可选 | `role` 范围或例外（取值 `exclusion` 表示例外区） |
| `units` 填图单元表 | 表格 | 可选 | `code` 代号（必需）、`name`、`category`、`age_ma`、`group`、`favorable` |
| `hematite`、`chlorite`、`hydromica`、`calcite`、`dolomite` 蚀变识别结果 | 单波段栅格 | 可选 | 非零像元表示识别出该类蚀变 |

## 处理规则

- **任务资料**：上传文件通过既有导入服务登记为数据资源，设为仅上传者可见（`owner_only`），来源标记为 `workflow-upload:<批次>`，不进入数据目录、搜索、算子输入候选、地图图层列表、后台数据管理和各类统计。一个批次只能被一个任务使用，创建任务时绑定。未绑定的上传可以删除。
- **登记事务**：单份资料独立提交；登记前锁定上传者记录并重新核对批次配额，避免并发请求超过12份。锁定使用不改变值的数据库更新，不改变用户登录时间。
- **字段确认**：智能体依据字段名、类型、示例取值和取值个数提出对应关系，每项给出理由。回答必须引用真实字段；缺少必需字段时任务停在确认环节，由用户选择。模拟模型使用字段名和取值规则给出建议。
- **工作副本**：确认后，平台按对应关系生成字段名规范化的工作副本，原上传文件不变。图斑和构造编号一律由平台按顺序生成中性编号，原文件中的编号不进入检查，避免编号中携带的评价标签进入算子和模型；缺少代号时以名称作代号；超出研究区的构造线裁剪到研究区；未提供研究区时取地质图范围；未提供构造线时使用空构造图层；未提供的蚀变类型使用全零栅格，并在计划中标为"未提供"。工作副本生成中途失败时，已生成的副本全部停用，重试从头生成。
- **分段**：只有地质图时运行岩性段；提供构造线或蚀变结果时运行综合流程。
- **规则与单元**：规则使用当前项目知识库中已显式绑定的综合推理试用规则。上传填图单元表时，表中的代号属性和名称映射覆盖默认单元表；未覆盖的代号不参与依赖单元属性的规则，报告中注明。
- **投影**：面积和距离计算的投影按地质图中心所在的 UTM 带推算。
- **执行引擎**：工作副本准备完成后，复用综合推理的四个已发布算子及其决策、批准和复查流程。
- **处置建议校验与批准**：疑点和建议数量不设30项上限。完整清单按要素、规则、动作、目标代号、状态和快照分组，模型根据数量、实测范围、代表样本及规则例外决定整组采用、整组待裁定或排除个别对象。review/exception 不得整组自动纳入。同对象多组按原检查顺序采用首条已选择建议，后端展开后逐对象校验快照、允许动作、目标代号及知识引用。批准卡片按组展示，支持整组选择与逐对象取消；实际修改、报告和复查仍基于展开后的对象。keep/review/downweight/exclude 的多余 target_code 忽略；相同逐项建议去重，不同逐项建议冲突保留首个合格项。首次失败返回序号、issue_id及原因，供模型在原有一次重试内修正；仍不合格时只将合格且唯一的建议送入批准，全部不合格则失败。editValidation 保存未采用原因，未采用项不执行，平台不补造依据。

## 入口

逻辑推理项目（项目编码 `02`、`demo-geology-reasoning`，与后端 `GEOLOGY_PROJECT_CODES` 一致）中，智能体页面只有一个模式：访问快速对话会转到智能体页面（当前账号没有科研智能体权限时保留快速对话），不显示模式切换。输入区不显示"调用算法""选择数据""知识库"，三者按默认自动处理；第一个按钮是"逻辑推理"，展开紧凑资料面板，不显示研究场景和知识依据选择。“选择系统数据”“上传文件/ZIP”并列，面板可收起而不丢弃选择，清空是独立操作。收起时显示已选数量；要求有可编辑的默认文案。不加载该流程不用的算法目录、算子候选、项目资料下拉及场景预设。思考强度使用与其他项目相同的滑杆，轻量默认对应fast，标准、深入对应deep+medium、deep+xhigh，不显示深度思考开关。其他项目的智能体页面不变。

系统数据按最近更新时间分页，支持搜索、目录（现有存量数据组别）筛选，显示类型、登记时间及总数。确认字段后按用户与项目保存系统数据部分的可复用配置；新会话打开资料面板自动恢复有效引用、角色、字段、要求和强度。发送时重新鉴权并匹配全部系统资源、更新时间与画像；一致且包含系统地质图才显示“沿用上次已确认的角色和字段”，不重复核对，计划和逐项批准仍须本次确认。临时上传及其角色、字段不进入配置，临时地质图和失效引用需重选；本次计划批准前可一键重新核对角色和字段。

上传后显示“智能体已识别资料角色，请核对后生成执行计划”，每份资料有理由和可编辑角色。真实模型只接收资料画像，非法或失败回答退回规则，明确标注“按文件名、类型和几何判断”；缺地质图时提示用户补选。安全解包拒绝路径穿越、链接等危险条目，最多512条目、解压量不超过平台uploadMaxMb与512MiB的较小值，忽略系统与旁车文件，不展开嵌套ZIP。

面板提前显示本人账号挡路任务的名称、场景、状态与更新时间，支持查看和二次确认取消；同账号跨项目仍只允许一个活动工作流。跨项目摘要不含资料，详情和取消继续校验目标项目权限。

## 接口

- `POST /api/agent/workflow-uploads/batch/`：重复 `files` 字段批量上传，返回 `{items,errors}`，逐份错误不撤销成功资料。
- `POST /api/agent/workflow-uploads/recognize/`：`{batchId,model}` 识别角色，返回建议、理由、问题及模型/规则来源。
- `GET /api/agent/workflows/active/`：读取本人账号活动任务摘要，详情及取消沿用原接口。

- `POST /api/agent/workflow-uploads/`：上传一个文件，`batchId` 为客户端生成的 32 位十六进制批次号。
- `GET /api/agent/workflow-uploads/?batchId=`：列出本人在当前项目该批次的上传。
- `DELETE /api/agent/workflow-uploads/{uploadId}/`：删除尚未绑定任务的上传。
- `POST /api/agent/workflows/`：`workflowType=geology_generic`，`uploadBatchId` 指定批次，`inputs` 把角色绑定到批次内的资源。
- `POST /api/agent/workflows/{workflowId}/confirm/`：字段确认环节提交 `fieldMapping`。
- 工作流详情的 `plan.fieldMappingReview` 返回智能体建议与可选字段。

## 权限

上传与运行需要的权限一致：智能体访问、MH-workflow、智能体调用算子，以及当前项目的数据登记权限。上传资料只对上传者和超级管理员可见。

## 第二期

规则由知识库生成并在计划确认时核对；未提供的蚀变类型改为算子可选输入；任务删除时清理任务资料；数据目录隐藏任务资料。
