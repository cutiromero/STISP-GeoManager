# 重复工作治理与效率回归

相同输入、相同数据版本与相同授权范围内的工作应有统一执行入口。复用只减少重复读取和纯计算，不替代权限、数据版本、执行授权或结果质量检查。

## 共享边界

| 工作 | 统一入口 | 复用范围 | 失效条件 |
| --- | --- | --- | --- |
| 资源概况、可视化统计、地图显示查询 | `api/client.ts`、`ReadFlights` | 当前页面相同键的在途请求 | 完成、失败、登录/项目/资源修订变化、写入或上传边界 |
| 瓦片就绪状态 | `hasCurrentVectorPreview` | 当前登录与项目中刚核对的描述符或未就绪状态，最长30秒 | 到期、写入、来源变化；从浏览器存储还原的描述符重新核对 |
| 无属性筛选的显示几何 | `cached_display_query` | 版本匹配的持久结果；进程间锁合并冷启动 | 资源修订、存储图层、完整查询参数或算法版本变化 |
| 输入版本准备 | `version_lock`、`storage_lock` | 同一资源版本的独立输入快照 | 源身份、内容、依赖或授权变化 |
| 同步操作内的文件摘要 | `checksum_scope` | 文件描述符和路径身份均未变化的同一同步操作 | 操作结束、异常、替换、尺寸/时间/模式变化 |
| 智能体进度与历史事件 | `load_run_activity` | 当前HTTP响应内一次批量读取 | 每次请求重新读取；不缓存权限或进度 |
| 智能体上下文来源 | `reusable_context_sources`、`check_context_sources` | 同次构建使用已读取并核对的精确来源列表 | 下一次生成、恢复或实时检查重新读取并授权 |

前端完整响应不在完成后继续缓存。多个使用者分别取得数据副本；取消一个使用者只取消其等待，最后一个使用者离开才中止底层请求。共享键包含登录代次、项目、资源编号和修订、语言、读取种类及完整参数。读取开始时固定参数和语言，响应返回时再次核对登录与项目归属。显式精确查询、导出和写操作不因显示请求合并而被重放。

瓦片状态复用只避免立即重复核对已知就绪情况，不是权限凭据。实际查询和瓦片请求仍由服务器鉴权。正、负状态均有时限，离线准备完成后不会因永久缓存“未就绪”而始终无法升级。

显示几何在缓存未命中时，经固定数量的存储锁协调HTTP线程、其他Web进程及后台预热。相同缓存写入目标互斥，不同版本分别核验，旧计算不能在新计算之后覆盖当前版本。锁文件数量有界；等待超时沿用503和Retry-After。缓存命中及等待方复用不占执行槽，真正计算仍服从原并发上限。属性筛选和精确业务查询保持各自原语义。

每个请求都独立检查当前用户、项目和资源访问权。不得把准入结果存入共享计算或持久缓存。失败不缓存为成功；进程退出自动释放存储锁，后续请求可以重试。

智能体序列化单次运行或整段会话时，用一次事件查询读取思考和用量，并在数据库内选择各运行最新的参数和回答预览。不得逐轮重复查询事件，也不得把历史累计预览全部取出后再丢弃。增量事件游标独立保留，完整思考、用量统计和终态表现保持一致。批量读取不代替每轮资料和知识的权限检查；下一次轮询必须看到新增事件。

实时上下文核对直接取精确来源列表并检查数量，避免先COUNT再读取；构建上下文时沿用该次核对所得的来源编号，不能再次查询另一份来源列表。此复用只在当前同步操作内生效，不跨模型请求缓存访问决策。历史资料被撤权、来源被删除或当前选择改变时，下一次实时核对仍拒绝继续使用。

仅存在结构化知识或文档引用时才解析知识范围。空依据和仅有数据资源的检查不应触发知识路由及其历史主题查询；真实知识引用仍逐次核对范围、版本和访问权。

## 科学结果一致性

栅格输入摘要保持原来的“所有有效像元值字节，再接所有掩膜字节”顺序。一次分块读取同时取得值和掩膜，掩膜使用最多8MiB内存的临时流顺序保存，超出后使用自动清理的私有临时文件；值摘要完成后拼接同一批掩膜字节，不重新读取原像元，也不让NoData派生掩膜触发第二遍数据读取。正常有效值、NoData和独立掩膜均须与原摘要完全一致，不能修改摘要协议或重建科学算子来掩盖差异。

复用已存在的输入版本时仍重新授权；算法取得独立inode的工作文件。几何量化、PNG/XYZ、MVT或缓存资料不能代替精确计算输入。原始文件、已冻结算法版本和任务绑定保持独立可核对。

独立科学任务和用户明确要求的重算不合并，不跨任务用旧算子输出冒充新执行。随机算法、规则修订、不同参数、不同输入版本或不同授权范围应分别处理。

## 必过检查

在项目既有运行环境中执行：

```bash
make check-efficiency
```

也可显式指定同一运行环境：

```bash
make check-efficiency EFFICIENCY_PYTHON=/path/to/project/python
```

该入口执行后端`efficiency`标记测试、前端在途共享单元测试和真实浏览器SDK回归。`build:verify`另外包含快速前端效率检查。涉及读取、校验、缓存或准备流程的提交与发布必须运行上述完整入口，并把结果放入验收回执。

回归断言覆盖：

- 相同并发冷请求只实际计算一次，缓存命中不占执行槽。
- 版本改变分别计算，旧版本不能覆盖新版本。
- 文件锁跨进程互斥，异常和进程退出后可重试。
- 多组件读取只发一个请求，结果副本互不污染。
- 单个取消不影响其他使用者，全体取消终止传输，随后可立即重试。
- 登录代次、项目、版本和参数不同不合并；写入后不复用旧的在途请求。
- 来源数量从1增加到50时，授权查询次数不逐对象线性增长；撤权仍立即拒绝。
- 文件修改、替换和中途变化使旧摘要失效。
- 栅格像元解码次数减少，旧、新科学摘要及原始文件字节完全一致。
- 智能体完整进度只查一次事件；30轮会话同样只查一次事件，轮询另保留增量游标查询。
- 智能体只提取当前参数和预览，下一次轮询读取新事件；已完成运行不再展示旧预览，思考时长和用量不丢失。
- 上下文来源只读取一次；精确祖先编号、撤权和来源删除检查保持有效。

新增昂贵调用应给出调用位置、输入身份、执行所有者、复用范围和失效条件，并提供相应的操作次数回归。不得只验证最终成功，或把减少权限与质量检查当作性能优化。新的后台线程、HTTP客户端和缓存层应复用统一入口，避免各自再实现一套。
