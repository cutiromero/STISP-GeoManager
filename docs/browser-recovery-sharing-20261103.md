# 浏览器兼容、白屏恢复和邀请分享

日期：2026-11-03；代码版本0.1.52，是否已上线以同提交正式回执为准。

## 白屏调查结论

用户报告szf在当天7:00—9:00多次切页后整页空白，其他电脑暂未遇到，浏览器版本尚未取得。

本次检查时正式0.1.51健康、模型/知识服务可达，szf账号有效，科研任务成功；服务器日志尾部没有对应500或静态404。当前浏览器使用独立验收账号完成15次页内切换，无脚本异常；这些检查不能还原szf当时浏览器的调用栈。

确认的代码缺口：

1. 多处无保护使用AbortSignal.any，旧浏览器会抛TypeError；工作流effect抛错可导致React根卸载。
2. 路由和页面没有异常恢复边界；首次懒加载失败还会被React.lazy缓存。
3. 权限复查把网络/5xx失败当作退出登录；畸形模型/预算配置可能进入渲染。
4. SPA入口HTML没有明确禁止缓存，跨部署保留旧入口可能引用失效静态模块。

本轮增加兼容取消工具、请求完成后的监听清理、页面/应用恢复边界、懒加载重试、权限瞬时失败保留会话、配置形状校验及HTML no-store。模块尚未加载时也有静态提示及浏览器信息，避免入口失败时只剩背景。

恢复页可重试、回地理工作台或两种对话；异常信息保存于浏览器sessionStorage的`platform:last-page-error`，包括时间、路由、错误和组件栈。只保存在该浏览器会话，未上传聊天内容。用户再次遇到问题时，可展开异常信息转给管理员。

较旧浏览器兼容缺口与现象相符，但未取得szf实际版本/异常信息，现场唯一根因尚未确定。浏览器扩展、缓存、GPU驱动或内存也需要结合现场证据判断。

## 浏览器要求

项目安装的Vite8实际默认构建目标：

| 浏览器 | 构建语法基线 | 日常建议 |
| --- | --- | --- |
| Chrome / Edge | 111及以上 | 使用当前受支持稳定版本 |
| Firefox | 114及以上 | 使用当前受支持稳定版本 |
| Safari / iOS Safari | 16.4及以上 | 使用当前受支持稳定版本 |

这是构建目标，不是每个版本均做过完整实机验证。IE和旧内核“兼容模式”不在支持范围；国产双核浏览器须使用较新的Chromium极速内核。更新浏览器后旧机是否顺畅还取决于地图规模、GPU/硬件加速和内存。

原生AbortSignal.any要求Chrome/Edge116、Firefox124、Safari17.4；它高于上述构建基线。已通过统一兼容工具消除这项额外门槛。语法转译不会自动补齐所有浏览器Web API。

地图使用Mapbox GL JS3，另外需要WebGL2。浏览器过旧、禁用硬件加速或驱动不支持时，地图能力会受限；普通文字对话不需要地图GPU能力。没有现场信息时，不把白屏直接归咎于电脑硬件。

依据：安装包`frontend/node_modules/vite/dist/node/chunks/logger.js`中的ESBUILD_BASELINE_WIDELY_AVAILABLE_TARGET，以及[MDN浏览器兼容数据](https://github.com/mdn/browser-compat-data/blob/main/api/AbortSignal.json)。本次读取的支持版本为2026-11-03核对值。

## 邀请分享的操作

工程面板、专题卡片/管理列表、计算任务单份输出增加“分享”。输入完整用户名，先核验目标项目成员关系、功能权限和底层资料访问权，再发出邀请；不使用用户下拉列表。

接收人通过顶部铃铛“分享通知”查看收件箱，选择接受或拒绝。分享者在发件箱看到处理结果与未读提醒。通知跨本人有权项目汇总，持久保存；页面获取焦点、打开或操作后刷新，常驻页面每60秒检查一次，不是即时推送。

接受前不增加授权；接受后只授该工程/专题/单份计算输出的只读访问，不开放整个计算任务或其他输出。下载仍需导出权限；不自动添加项目成员或突破owner_only。发出、接受和打开均重新核验，资料删除或撤权后返回明确不可用原因。

结果文件通过接受的邀请单独预览/下载；地图型结果继续使用原有工作台预览。实际地图预览能力取决于该输出类型。

同一分享重复发送复用活动邀请；接受/拒绝有原子状态检查和幂等处理。收到畸形响应或暂时404时通知组件保留原页面，错误仅在通知模块呈现。
