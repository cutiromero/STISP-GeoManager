# 平台API与Agent能力开放规范

## 能力准入

业务接口表达能够独立验证的业务操作。查询资料、保存个人工程、提交计算、导入成果、发布和分享需要明确合同；面板展开、悬停和临时选中通常由前端管理，不为这些状态建立业务数据接口。需要由智能体改变当前浏览器时，采用受控前端动作，不把保存工程等同于已经加载用户页面。

业务API服务网页及已授权客户端，Agent工具在同一业务服务上增加用途、参数、影响和执行规则。具备后台接口不等于向Agent开放；未登记工具默认不可执行。原件删除、任意SQL、服务器路径操作、系统命令及权限提升不进入普通Agent能力。模型返回的文字和工具观察不能授予权限或代替人工批准。

## 唯一合同与发布门禁

`docs/openapi.yaml`为唯一API和工具参数合同。`x-agent-tools`登记工具语义版本、参数schema引用、实现类型、业务operationId、影响、风险、授权、幂等、重试、完成判据和限制。共享业务服务引用真实operationId；只作用于智能体内部的证据比较、站内链接等声明internal_service，不虚构HTTP对应关系。输入参数复用已存在的业务schema；专属工具参数使用AgentTool系列schema。`scripts/generate_agent_contracts.py`生成`backend/apps/agent/tool_contracts.json`，前端SDK及DTO沿用OpenAPI生成，不手工维护生成物。

生成器必须检查每个实际ToolSpec均有合同、合同无多余工具、operationId真实存在、顶层拒绝未知参数且参数与注册表一致。新增工具同步合同、注册表、后端授权与正反例、必要前端及模拟响应；构建运行`agent:contracts:check`。合同不一致时停止发布。

`GET /api/agent/capabilities/`按当前用户和唯一项目返回允许发现的能力。目录不读取科研像元、不调用模型、不执行业务写入，不包含凭据、服务器绝对路径和用户资料正文。目录不替代执行时权限核验；联网能力还需具体会话的显式开启。

## 执行合同

通用工具执行时按生成的有界JSON Schema子集检查类型、必填、枚举、格式、范围、数组和互斥方案；生成器拒绝运行时未支持的校验关键字。固定算子的inputs和parameters由实际冻结manifest的专门校验处理，以保留真实输入键及缺参引导。统计默认字段、分组默认count、整数知识文献编号及Agent的field/op/value筛选语义保持一致。

真实调用保存为AgentToolCall回执，关联本人运行、项目、合同版本、影响、参数名称、参数SHA-256和实际对象引用。失败保存稳定错误码、关联号和字段问题，不保存参数值、文档正文或原始像元。GET /api/agent/runs/{runId}/tool-calls/仅允许本人在当前项目分页读取，历史来源撤权后沿用运行历史访问边界。回执中的succeeded表示工具调用成功，计算、质量及入库仍以实际任务状态为准；回执跟随所属运行历史保留。

1. 当前身份、唯一项目、任务及会话绑定来自服务端上下文，不接受模型传入owner或自行扩大项目。
2. 参数说明包括类型、必填、枚举、默认值和范围；地理操作同时明确CRS、分辨率、单位、时段、波段与NoData。动态算法参数仍取冻结的真实manifest。
3. 只读操作明确分页、截断和统计口径；摘要、抽样与近似统计不能冒充全量精确结果。
4. 写入使用稳定幂等键和内容摘要；相同键不同参数拒绝。返回旧回执前重新检查当前权限、对象修订和来源资格，不能以幂等绕过撤权。
5. 修改已有对象必须带最后读取修订。冲突后重新读取，不覆盖其他会话的新状态。耗时处理与短数据库写事务分离。
6. 长任务复用现有队列、任务与状态接口；受理、计算成功、质量通过和入库完成分别表示。取消阻止后续执行，不代表已完成成果被撤销。
7. 错误保持detail兼容，机器可读错误码、字段差距、重试建议和关联号不得泄漏被拒绝的对象内容。参数、权限和质量失败不盲目重试；繁忙按Retry-After有限退避。
8. 审计关联真实用户、项目、会话、运行、工具和实际任务/对象。不得把调用参数中的秘密、文档正文或原始像元写入通用日志。科研成果保留输入、算法、参数和适用时的随机种子版本。

## 授权等级

| 影响 | 执行边界 |
| --- | --- |
| 查询与只读统计 | 当前用户权限、项目、资料ACL及资源预算 |
| 个人引用工程草稿 | 已授权的低影响创建，不写原件、不扩大可见范围 |
| 计算与导出 | 明确输入、参数、时段及资源预算，复用既有任务状态 |
| 新资料或成果入库 | 明确导入对象、目的项目及授权；预检通过后沿用标准导入服务 |
| 发布与分享 | 具体对象、修订、接收人或发布范围的预览与真实用户决定 |
| 删除原件与权限提升 | 不向普通Agent开放 |

确认绑定具体对象、范围、修订、调用人及有效期。Agent提供`confirmed=true`不构成人工批准；有效的既有授权按范围复用，不逐步骤重复弹窗。专业科学审批与通用发布确认独立，任何通用能力不得写入伪造的human.approved。

## 分阶段交付与验收

| 阶段 | 交付 | 上线前验收 |
| --- | --- | --- |
| 1 | 规范、生成器、26项既有能力合同、授权发现API、SDK与构建门禁 | 合同一致性、未登录/缺项目/撤权拒绝、策略过滤、无资料写入 |
| 2 | 执行时参数合同、结构化错误、统一可用性及审计边界 | 参数和嵌套错误、策略变化、模型错误恢复、既有工具及效率回归 |
| 3 | 个人工程读取/修订、任务控制、成果读取与异步导出链 | 真实对象/修订、重复提交、取消、撤权、文件读取及原件一致性 |
| 4 | 新增资料导入、发布/分享的受控预览与真实决定、完整验收 | 预览过期/换版/撤权/越权拒绝、重复确认、专业门禁保留、端到端验收 |

每阶段在固定个人分支完成代码备份，通过统一候选、切换及正式验收后继续下一阶段。验收使用隔离候选合成资料，不修改生产原件、原表和既有专业批准；保留逐阶段提交、回执及清理结果。
