# 业务流开发规范

## 执行架构

新业务流使用 `executionMode: main_agent`。一个任务只有一个主执行智能体，持续负责理解目标、选择可执行目标、查询登记算子、组织输入、预检、计算、检查结果、纠错及撰写报告。字段理解和资料衔接代码生成属于主执行者的工作，不为每个节点创建新的执行智能体。

节点定义目标、依赖、可用工具、交付物及必要审核边界。平台维护持久状态、队列、授权和工具执行；智能体选择实际行动。节点完成不等于任务完成，模型自报完成不等于真实计算成功。

独立模型仅用于需要独立判断的审核。简单读取、统计、节点切换和状态汇总不增加审核请求。资料不足应返回具体缺口，不能用多次审核替代缺失资料。主执行者根据具体退回意见修正，避免重复生成无变化的方案。

旧发布版本保持原执行语义；发布新版本后才改变新任务的默认行为。暂停与恢复保留同一主执行身份和冻结的技能版本。

## 定义与配套技能

流程定义包含输入规范、目标依赖、工具范围、登记算子及参数默认值、必需输出、可选审核策略和短技能。依赖图无环，最多32个目标。

技能核心最多600字符，每节点指导最多300字符。核心说明共同方法：先看证据，先预检后计算，按诊断调整，保留成果引用，不能伪造成功；只在对应目标注入节点专项说明。技能不能覆盖授权、核心算法或人工决定。

为能力有限的模型提供短而具体的步骤、实际输入端口、示例和可操作的诊断。避免要求模型同时维护多份相互重复的协议、逐字抄写验收条件、猜测内部字段或在报告中复述平台实现。格式应简单稳定，科研分析不能用固定套话代替。

## 算子与参数

算子查询以当前用户、项目和发布版本为准。新主执行模式提交计算前，必须对相同版本、输入、参数和字段映射完成真实预检；任何有效方案变更都重新预检。

算子核心代码、登记校验和、科学规则来源和实际处置批准凭据受保护。输入输出绑定、字段与波段，以及清单中 `agent.adjustable=true` 的参数，由主执行者依据实际资料决定。参数默认值是起点，不是跨资料通用答案；例如 NDVI 的红光和近红外波段应依据真实波段信息绑定。

同一错误可尝试不同参数或字段映射。禁止重复提交同一错误下的相同实际方案，不能仅因为补救类别相同就禁止再次调整。错误以 `code / remedy / gaps` 返回，包含受影响输入、允许修改范围及可行下一步。平台故障、权限撤销和不可恢复错误不得盲目循环重试。

文件与成果通过平台引用和校验和交接。原始文件路径不授予读取权限；引用也不代表模型已经读过内容。按需读取有界片段或完整统计，不能把原始文件全文放入提示词。

## 校验分层

| 层次 | 校验依据 | 处理方式 |
| --- | --- | --- |
| 执行授权 | 当前用户、项目、实际资料权限、可用工具、控制代次 | 每个执行边界检查；不由模型豁免 |
| 科学与数据合同 | 算子版本、端口、参数范围、输入类型、质量标记、批准范围 | 拒绝无效执行，返回具体诊断 |
| 完成交付 | 必需输出名称及语义、真实成功任务、实际证据引用 | 缺项不能完成；不要求逐字复述验收条件 |
| 独立审核 | 结论与实际结果、关键证据、已配置的验收目标 | 仅必要节点启用，退回必须具体可执行 |
| 展示与写作 | 表述、章节顺序、推荐主题、术语风格 | 用提示指导，不能仅因措辞中止任务 |

审核接受时，引用必需证据、实际计算输出和当前执行结果。其他辅助索引只需引用实际采用的部分，不要求机械抄写全部编号。伪造引用、非法人工批准、相互矛盾的通过结论仍不接受。

人工决定只通过本人在当前项目对当前修订提交的实际审批记录产生。模型、脚本审阅或节点恢复均不能写入人工批准。质量为 `needs_review` 不因一般节点批准而自动变为通过。

## 上下文与 token

| 限制 | 目的与作用范围 |
| --- | --- |
| 模型实际窗口 | 服务本身能处理的单次请求容量，不能绕过 |
| `maxContextTokens` | 管理员配置的单次输入上限，完整请求用服务分词器测量 |
| `maxOutputTokens` | 单次生成额度，支持思考的服务可能将思考与正文共用此额度；不是整条任务累计 token 上限 |
| `maxContextBytes` | 防止异常大的请求和序列化开销，不能替代分词 |
| 模型请求、算子次数和节点累计时间 | 防止失控循环及无限计算；与输入窗口、单次输出 token 分开计量 |

当前系统未设置业务流累计输入、累计输出 token 的总额度；任务用模型请求次数和算子次数限制循环。输入可用空间同时受配置输入上限及实际窗口减去输出预留和安全余量约束。执行、独立审核及返修不额外套用固定32K输入上限，不能无提示地改变用户选择的思考强度。

自动整理优先使用平台函数，不增加执行子智能体：

1. 精确去重，按成果引用传递，省去重复的大型属性与几何信息。
2. 压缩历史行动和较早台账，保留当前任务、最新观察、未解决限制及成果引用；必要时通过 `read_task_record` 回顾已完成目标。
3. 有界投影普通样本和辅助资料，记录原始规模、保留规模及省略范围。
4. 通用资料仍超预算时才使用既有分批摘要功能。它只整理辅助资料，计入实际请求与审计，不承担节点执行。完整统计、规则条件与例外、真实参数、当前执行结论和批准依据不得交给有损摘要替换。

专业计算工具请求采用精确去重及行动历史压缩，保持完整科学事实；专业判断沿用科学事实投影。无法容纳必要事实时保留当前结果并等待处理，不能裁掉必要证据后宣称完成。调整窗口、输出预留或输入范围必须在实际服务能力和当前授权内进行。

压缩不自动改变统计口径，不把样本当成全集，不把摘要当成原始资料。每次请求记录实际输入 token、窗口、输出额度、压缩档位和思考设置。

## 循环预算

| 节点配置 | 默认值 | 平台允许上限 |
| --- | ---: | ---: |
| `maxSteps` | 32 | 128 |
| `maxModelCalls` | 32 | 128 |
| `maxOperatorCalls` | 6 | 32 |
| `maxRecoveries` | 4 | 8 |
| `maxSeconds` | 3600 | 14400 |

节点 `maxSeconds` 是多轮模型和工具主动处理的累计时间；策略 `maxRunSeconds` 是单次请求时限。两者分别检查，不能用单次时限压住整个节点。排队和人工等待不累计为主动处理时间。

任务级切换目标和最终结束请求只计入任务模型额度，不能扣到前一个已完成节点。执行、脚本生成、必要审核和上下文归纳均按真实请求计量，重试与恢复不清零计数。用完最后一次补救后，已提交计算仍应正常收集结果。

任务模型基础额度沿用 `maxSteps` 策略转换：非零时为至少4次、至多256次的两倍策略步数；零时保留256次平台保护。默认策略32步的基础额度为64次请求；主执行模式另外预留目标数量加1次的必要调度开销，七目标为72次，32目标为97次，合计仍不超过256次。任务算子总额度来自 `maxOperatorSteps`，节点额度不能扩大任务授权。复杂流程发布前须评估正常路径、输入准备、必要审核及合理返修所需额度，不能只测试最短路径。

格式修复限制针对连续错误；有效动作之后清除本次格式错误状态，后续独立格式错误可再次修复，实际请求仍累计计数。

已显式配置的旧节点额度继续有效。需要放宽的已发布流程应发布新版本，不暗中改写用户进行中的合同。

## 报告与成果

报告模板负责结构，算子和平台负责真实统计、表格、地图、引用与附件。主执行智能体负责具体分析，并区分计算事实、地质解释和待验证假设。不能以模板文案或算子建议冒充模型分析。

逻辑推理使用已有 `decision` 结构：`resultSummary` 提供关键结果综述，`findings` 保存综合分析正文，`uncertainties` 说明局限。推荐分析问题成因、处置效果与剩余问题、岩性构造蚀变的关系、远景意义及后续验证。主题按资料适用性取舍，不要求固定字数或段数；缺资料时说明具体缺口。

新的主执行任务在报告分析缺失时返修；不能只返回数字综述就完成报告。独立审核检查完整报告分析和同一份真实事实。下载文件必须包含已接受的 `findings`，排在自动统计与详细处置资料之前。报告导出只渲染已接受内容，不重新调用模型、不重算科学结果。

## 搭建与验收

新增业务流沿用目录、版本、输入准备、主循环、计算队列、批准与报告服务，不另建一套调度。优先短技能和清晰工具合同；只有确实不同的科学适配边界才增加专业代码。

发布前覆盖正常路径、可修复参数错误、同错误不同方案、真实失败、人工等待与恢复、暂停停止、撤权及报告分析入文。模型桩用于验证状态和边界；真实科学样例用于验证计算一致性。两者均不能替代正式网站操作。

最终验收必须使用正式网站的可视化界面，在真实用户项目启动、处理必要人工节点并完成任务，核对节点实际调用、主执行连续性、独立审核、分析正文及成果下载。服务器不可用时只记录本地验证，正式验收保持待办。
