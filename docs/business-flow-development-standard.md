# 业务流开发规范

## 执行架构

新业务流使用 `executionMode: main_agent`。一个任务只有一个主执行智能体，持续负责理解目标、选择可执行目标、查询登记算子、组织输入、预检、计算、检查结果、纠错及撰写报告。字段理解和资料衔接代码生成属于主执行者的工作，不为每个节点创建新的执行智能体。

节点定义目标、依赖、可用工具、交付物及必要审核边界。平台维护持久状态、队列、授权和工具执行；智能体选择实际行动。节点完成不等于任务完成，模型自报完成不等于真实计算成功。

独立模型仅用于需要独立判断的审核。简单读取、统计、节点切换和状态汇总不增加审核请求。资料不足应返回具体缺口，不能用多次审核替代缺失资料。主执行者根据具体退回意见修正，避免重复生成无变化的方案。

旧发布版本保持原执行语义；发布新版本后才改变新任务的默认行为。暂停与恢复保留同一主执行身份和冻结的技能版本。

## 定义与配套技能

业务流登记归属一个项目。项目专用流程只在所属项目发现、查看和启动；通用流程登记在公开项目，供各项目复用定义，任务、资料、会话和成果仍归启动时的当前项目。共享定义只在登记项目维护；当前项目有同编码定制版本时优先展示本项目版本。预置逻辑推理归核地院逻辑推理项目，初始化其他项目不重复登记。

流程定义包含输入规范、目标依赖、工具范围、登记算子及参数默认值、必需输出、可选审核策略和短技能。依赖图无环，最多32个目标。

技能核心最多600字符，每节点指导最多300字符。核心说明共同方法：先看证据，先预检后计算，按诊断调整，保留成果引用，不能伪造成功；只在对应目标注入节点专项说明。技能不能覆盖授权、核心算法或人工决定。

为能力有限的模型提供短而具体的步骤、实际输入端口、示例和可操作的诊断。避免要求模型同时维护多份相互重复的协议、逐字抄写验收条件、猜测内部字段或在报告中复述平台实现。格式应简单稳定，科研分析不能用固定套话代替。

## 算子与参数

算子查询以当前用户、项目和发布版本为准。新主执行模式提交计算前，必须对相同版本、输入、参数和字段映射完成真实预检；任何有效方案变更都重新预检。方案身份采用计算中心规范化后的实际参数、字段映射和集合绑定；省略默认值与显式填写同一默认值属于相同方案。

缺少预检或方案凭据不匹配属于执行前置条件，返回`PREFLIGHT_REQUIRED`并指明先调用`preflight_operator`。此时尚无计算提交，不记为科学算子失败，不要求改动有效科研参数，不消耗算子补救额度。通过预检后可以按原方案计算；真实计算失败仍按诊断检查补救方案、重复尝试及原有额度。

算子核心代码、登记校验和、科学规则来源和实际处置批准凭据受保护。输入输出绑定、字段与波段，以及清单中 `agent.adjustable=true` 的参数，由主执行者依据实际资料决定。参数默认值是起点，不是跨资料通用答案；例如 NDVI 的红光和近红外波段应依据真实波段信息绑定。

同一错误可尝试不同参数或字段映射。禁止重复提交同一错误下的相同实际方案，不能仅因为补救类别相同就禁止再次调整。错误以 `code / remedy / gaps` 返回，包含受影响输入、允许修改范围及可行下一步。平台故障、权限撤销和不可恢复错误不得盲目循环重试。

文件与成果通过平台引用和校验和交接。原始文件路径不授予读取权限；引用也不代表模型已经读过内容。按需读取有界片段或完整统计，不能把原始文件全文放入提示词。

固定算子节点绑定的核心版本不能由工具调用替换；需要自主选择算子时使用带执行合同的智能体节点。`inputBindings`中的资料角色即使未在`dataRoles`重复列出也属于该节点输入。显式成果连线可引用依赖链中已完成且通过审核的祖先节点，只开放连线声明的具名成果，不自动开放其他祖先资料。

主执行合同声明非分析成果时必须包含`run_operator`；运行工具同时需要`operator_catalog`、`preflight_operator`和正数`maxOperatorCalls`。发布时检查参数默认值的类型、范围、枚举和长度，不读取实际科研文件；字段、波段和来源语义在实际预检时核对。

## 平台校核与计算复用

校核按事实的变化范围执行，避免每层重新读取同一资料。输入元信息由计算中心统一读取；同一资源的多个端口只在本次准入中读取、鉴权一次。表格和矢量元信息绑定资源修订、物理文件身份、SQLite日志及读取选项，使用有界签名凭据与进程间锁复用。表格类型保持全量推断口径，不能通过只读首行将混合类型误判为数值。缓存不可写时回到严格读取，不把缓存失败当成输入通过。

预检凭据同时绑定版本、清单、输入修订和实际来源文件，以及参数和字段映射。来源或方案变化后重新预检。正式提交仍检查当前权限和数据合同；计算worker继续冻结并校验独立输入快照，预检不能替代执行边界。

成功计算只在同一任务、同一节点且方案与来源完全一致时复用。复用前核对当前授权、真实任务状态、成果归属、过期状态、文件存在性及校验和。独立任务、显式重算和变化后的输入分别执行。仅修改解释文字、修复报告格式或整理审核上下文时保留成功计算与成果引用；缺失或损坏的成果不能靠原成功状态继续交付。

同一任务的多个输出统一收集，在读取前后各核验一次任务和输入权限，每个输出仍核对自身完整性。收集覆盖全部非归档输出，不截断为固定前几项；组合观察超过容量时交付完整引用索引，按需读取各成果。不得逐输出重复查询同一任务权限，也不得为预览、审核、报告导出重跑科学算子。

## 校验分层

| 层次 | 校验依据 | 处理方式 |
| --- | --- | --- |
| 执行授权 | 当前用户、项目、实际资料权限、可用工具、控制代次 | 每个执行边界检查；不由模型豁免 |
| 科学与数据合同 | 算子版本、端口、参数范围、输入类型、质量标记、批准范围 | 拒绝无效执行，返回具体诊断 |
| 完成交付 | 必需输出名称及语义、真实成功任务、实际证据引用 | 缺项不能完成；不要求逐字复述验收条件 |
| 独立审核 | 结论与实际结果、关键证据、已配置的验收目标 | 仅必要节点启用，退回必须具体可执行 |
| 展示与写作 | 表述、章节顺序、推荐主题、术语风格 | 用提示指导，不能仅因措辞中止任务 |

审核接受时，引用必需证据、实际计算输出和当前执行结果。其他辅助索引只需引用实际采用的部分，不要求机械抄写全部编号。伪造引用、非法人工批准、相互矛盾的通过结论仍不接受。

人工决定只通过本人在当前项目对当前修订提交的实际审批记录产生。模型、脚本审阅或节点恢复均不能写入人工批准。质量为 `needs_review` 不因一般节点批准而自动变为通过。

## 错误、诊断与人工续接

业务流默认采用主执行智能体自查、有限自动补救、人工补充后续接的共同机制。格式、引用、模型服务和审核返修问题属于当前节点的可恢复等待；不能仅因自动补救耗尽就将整条任务置为失败，不能要求用户从头计算。

执行中的输入校验、算子计算、成果导入及平台异常均须提供人工交接入口，不要求节点预先开启人工审核。自动处理不能解决后，由原主执行智能体依据有界的错误事实分析原因，列出节点与动作、错误码、受影响字段或输入版本、期望与实际差距、真实尝试记录和用户需要采取的具体步骤。页面分开展示平台事实与可用分析，并提供任务、计算和模型请求编号。诊断服务未返回可用分析时，页面展示原始错误、执行记录和恢复入口，诊断状态保存在内部记录中。界面使用具体的任务状态和操作说明，已完成节点的结果摘要过滤临时审核进度。

每次交接至多增加一次诊断请求，继承原模型和思考强度，并计入原任务及节点预算；不建立诊断子智能体，不传文件全文、完整日志或全部历史。恢复保留准确的中断阶段；资料准备、成果导入和任务结束请求不能误跳到科学决策，已成功计算不因诊断或补充而重跑。

同一异常由拥有当前动作状态的循环处理。工具循环已有格式修正与原生工具回退时，模型传输层不得提前截获并转等待；外层只接收该循环最终交出的等待或终止结果，避免多层重试互相打断。

工具返回后若节点仍需继续，工作线程退出前须把任务交回`queued`；已有计算等待、人工等待和暂停停止状态保持有效。正常工具交接不能依赖失联任务恢复定时器推进。

| 问题类别 | 默认处理 |
| --- | --- |
| 动作、报告或审核格式错误 | 返回具体校验诊断，按原额度进行有限修正；仍不合法则保留响应与成果，等待补充后继续当前请求。 |
| 必需引用缺失 | 核对原始引用、有效引用和最新真实统计，逐项验证授权与修订；不得静默裁掉合法引用。 |
| 平台处理前后数据矛盾 | 记录为平台诊断，停止自动重复调用；人工核查或服务修复后重新验证，不能靠提示词绕过校验。 |
| 审核指出事实错误 | 由原主执行智能体按具体问题返修。自动返修用尽后等待人工补充，再继续分析并独立审核；不能将人工补充当作审核通过。 |
| 模型连接、生成或临时服务错误 | 保留已完成状态和实际响应记录，等待恢复，不将页面临时断联当作后台计算失败。 |
| 用户停止或权限撤销 | 用户停止、暂停仍立即生效；执行中撤权交接真实权限错误，须先恢复权限才能继续，人工提示不得授予访问权。 |

人工补充绑定本人、当前项目、节点、状态修订和幂等键，每次最多2000字。模型只接收当前有效的一条补充、最多1000字的诊断及必要成果引用，不累计全部对话、失败正文或文件内容。节点补充不传播到其他节点，任务调度补充也不充当节点指导；执行和审核分别只接收自己的补充。

恢复沿用同一主执行会话及冻结流程。科学计算已成功、仅分析文字需要修正时，保留实际任务及成果引用；相同版本、输入、参数与映射的成功计算不重复提交。确需改变算子方案时，仍使用原允许参数、实际预检和计算路径，不能用文字修改真实统计或覆盖原件。

`maxRevisions`限制每次自动推进期间的连续返修，不限制用户明确提出的新一轮修改。人工补充可以开启新的自动审核周期，但不重置累计尝试、模型请求、算子调用、主动处理时间或任务额度；达到实际硬上限时仍进入对应额度等待。恢复不产生 `human.approved`，修改后的结论仍经过原独立审核及必要人工决定。

新建流程可从 [可恢复分析模板](../examples/business-flows/recoverable-analysis.json) 或 [可恢复统计算子模板](../examples/business-flows/adaptive-statistics.json) 开始。模板保持一个主执行者和短技能，按业务需要配置审核，不复制新的调度或错误处理框架。

## 上下文与 token

| 限制 | 目的与作用范围 |
| --- | --- |
| 模型实际窗口 | 服务本身能处理的单次请求容量，不能绕过 |
| `maxContextTokens` | 管理员配置的单次输入上限，完整请求用服务分词器测量 |
| `maxOutputTokens` | 单次生成额度，支持思考的服务可能将思考与正文共用此额度；不是整条任务累计 token 上限 |
| `maxContextBytes` | 防止异常大的请求和序列化开销，不能替代分词 |
| 模型请求、算子次数和节点累计时间 | 防止失控循环及无限计算；与输入窗口、单次输出 token 分开计量 |

当前系统未设置业务流累计输入、累计输出 token 的总额度；任务用模型请求次数和算子次数限制循环。输入可用空间同时受配置输入上限及实际窗口减去输出预留和安全余量约束。执行、独立审核及返修不额外套用固定32K输入上限，不能无提示地改变用户选择的思考强度。

新配置的默认单次生成额度为16384，普通分析方案同为16384；标准账号在开启任务预算后可选择至多32768。实际仍受角色、执行及审核模型窗口约束，已有显式配置保持原值。输入配置上限49152和默认字节保护384000保持不变，不因输出额度提高而堆入更多文件内容。目录启动的预算选择必须通过API保存到父运行，执行、审核和返修沿用同一快照；来自会话工具的启动继承父运行预算。预算方案不自动改动明确选择的思考强度。

49152和384000是未选择任务预算时的默认保护。启用并选择已授权任务预算后，沿用现有预算服务：本次输入上限取角色允许窗口减生成额度及安全余量，字节保护至少为该窗口的8倍，再按模型实际窗口检查；这不是自动扩大文件输入的许可。生成预留增加会减少可用输入，复杂任务应同时核对两者。

界面区分总窗口与实际可用输入，生成预留占用窗口时必须如实展示。证据索引单次最多512项，完整请求遵循当前maxContextBytes，不另叠加固定96 KiB组合证据限制；工具的单次观察保护与请求总量保护分别执行。

自动整理优先使用平台函数，不增加执行子智能体：

1. 精确去重，按成果引用传递，省去重复的大型属性与几何信息。
2. 压缩历史行动和较早台账，保留当前任务、最新观察、未解决限制及成果引用；必要时通过 `read_task_record` 回顾已完成目标。
3. 有界投影普通样本和辅助资料，记录原始规模、保留规模及省略范围。
4. 通用资料仍超预算时才使用既有分批摘要功能。它只整理辅助资料，计入实际请求与审计，不承担节点执行。完整统计、规则条件与例外、真实参数、当前执行结论和批准依据不得交给有损摘要替换。

专业计算工具请求采用精确去重及行动历史压缩，保持完整科学事实；专业判断沿用科学事实投影。无法容纳必要事实时保留当前结果并等待处理，不能裁掉必要证据后宣称完成。调整窗口、输出预留或输入范围必须在实际服务能力和当前授权内进行。

压缩不自动改变统计口径，不把样本当成全集，不把摘要当成原始资料。每次请求记录实际输入 token、窗口、输出额度、压缩档位和思考设置。

## 循环预算

| 节点配置 | 默认值 | 平台允许上限 |
| --- | ---: | ---: |
| `maxSteps` | 32 | 128 |
| `maxModelCalls` | 32 | 128 |
| `maxOperatorCalls` | 6 | 32 |
| `maxRecoveries` | 4 | 8 |
| `maxSeconds` | 3600 | 14400 |

节点 `maxSeconds` 是多轮模型和工具主动处理的累计时间；策略 `maxRunSeconds` 是单次请求时限。两者分别检查，不能用单次时限压住整个节点。排队和人工等待不累计为主动处理时间。

任务级切换目标和最终结束请求只计入任务模型额度，不能扣到前一个已完成节点。执行、脚本生成、必要审核和上下文归纳均按真实请求计量，重试与恢复不清零计数。用完最后一次补救后，已提交计算仍应正常收集结果。

请求额度等待必须与输入窗口等待分开显示，准确传递等待类型、额度来源、实际用量及上限。专业流程的恢复控件只能提供后端支持的操作。任务额度不足时，管理员增加当前允许值后可在原任务显式继续，保留所有计数与已完成工作，并记录额度调整；没有获得更高额度时不得通过重试继续消耗请求。节点合同上限不能被任务额度增加覆盖。

审核连续格式失败后保留执行成果，进入可重试的审核等待，不把无正文或非法JSON当成审核结论。显式重试只请求该次审核，不重复计算；需要实质返修时仍由主执行者处理。恢复已保存响应时，使用该次请求的短任务记忆快照，实际科学输入、目标、权限、规则及批准范围继续重新核对，不能因台账随后新增记录就无故重发模型请求。

审核引用或字段不符合合同也可在同一预算内修正一次，诊断明确列出本次外层证据编号，修正后仍严格校验，不能直接视为通过。审核等待及重试不得改写已保存执行请求的计划状态提示；已接受响应按原请求身份复用。最终分析独立存于finalStage，历史重复尾记录只在其请求完全一致时收拢。旧任务因审核恢复中止但仍保存完整已接受执行响应与原审核诊断时，可从页面显式重试该次审核；其他失败不开放此恢复，所有计数、原始审批和科学校验继续有效。

平台明确记录了响应归一化前后必需引用不一致时，完整保存的被拒绝响应可以在问题修复后重新校验。恢复仍比较当前完整事实、请求摘要、字节数、模型及预算，并重新执行响应校验；原拒绝及后续返修记录保留，不能将未知引用或真正缺失的证据重新解释为有效。

任务模型基础额度沿用 `maxSteps` 策略转换：非零时为至少4次、至多256次的两倍策略步数；零时保留256次平台保护。默认策略32步的基础额度为64次请求；主执行模式另外预留目标数量加1次的必要调度开销，七目标为72次，32目标为97次，合计仍不超过256次。任务算子总额度来自 `maxOperatorSteps`，节点额度不能扩大任务授权。复杂流程发布前须评估正常路径、输入准备、必要审核及合理返修所需额度，不能只测试最短路径。

新配置的任务算子总额度默认为16次。专业七目标含5次科学计算，最多7份资料各准备一次时合计12次，保留4次计算余量；这是流程结构估计，不是历史调用次数统计。启动前核对已知正常路径的最低模型与算子需求，包含初始资料转换、脚本生成及其配置审核；已知额度不足时拒绝创建任务并说明最低需求。主执行专业流程至少需要27次模型请求，再加配置的节点AI审核与脚本请求；32个计算目标全部配置审核时最低193次，默认97次不能直接启动。

模型和算子任务额度耗尽均保留成果及待执行动作，进入相应额度等待。显式恢复仅接纳当前策略实际提高的允许额度，保留请求、算子、补救次数和方案签名；尚未提交的动作不能提前扣补救次数。初始资料准备没有科学阶段时也能继续原阶段，不能错误转入科学决策或生成批准记录。平台故障停止自动重试；用户明确恢复后清除当前阻断诊断，保留历史记录和全部计数，允许重新预检及执行。

格式修复限制针对连续错误；有效动作之后清除本次格式错误状态，后续独立格式错误可再次修复，实际请求仍累计计数。

已显式配置的旧节点额度继续有效。需要放宽的已发布流程应发布新版本，不暗中改写用户进行中的合同。

通用算子节点向主执行者提供冻结版本、参数和输入绑定的短精确预览；完整配置通过当前节点的 `node-config-<nodeId>` 引用按需读取，不自动加入长参数或脚本正文。固定参数允许原样复述，改变值仍须符合清单授权。计算节点交付的非分析成果必须来自本节点真实计算，不能用上游输出冒充；仅交付分析时也不能绕过规定的实际计算。

输入替换后仍须对当前输入和任务曾使用的来源合并进行批量权限核验；撤权的旧来源不能通过缓存、历史结果或恢复继续进入模型与计算。

## 报告与成果

报告模板负责结构，算子和平台负责真实统计、表格、地图、引用与附件。主执行智能体负责具体分析，并区分计算事实、地质解释和待验证假设。不能以模板文案或算子建议冒充模型分析。

逻辑推理使用已有 `decision` 结构：`resultSummary` 提供关键结果综述，`findings` 保存综合分析正文，`uncertainties` 说明局限。推荐分析问题成因、处置效果与剩余问题、岩性构造蚀变的关系、远景意义及后续验证。主题按资料适用性取舍，不要求固定字数或段数；缺资料时说明具体缺口。

新的主执行任务在报告分析缺失时返修；不能只返回数字综述就完成报告。独立审核检查完整报告分析和同一份真实事实。下载文件必须包含已接受的 `findings`，排在自动统计与详细处置资料之前。报告导出只渲染已接受内容，不重新调用模型、不重算科学结果。

## 搭建与验收

界面直接呈现任务目标、进度、结果、待处理问题和操作要求，使用“任务执行”“结果审核”“资料确认”等业务用语。权限不足、资料缺项或处置范围等限制说明具体原因与下一步；不添加泛化的AI免责声明、防御性自证或面向开发者的内部协议说明。模型选择及运行诊断放在对应设置与记录中。分析过程原文默认收起，按需展开；页面默认展示当前进度、结论和操作入口。格式、引用和预算等恢复等待仅展示相应的恢复操作，不同时展示科研批准控件。

新增业务流沿用目录、版本、输入准备、主循环、计算队列、批准与报告服务，不另建一套调度。优先短技能和清晰工具合同；只有确实不同的科学适配边界才增加专业代码。

发布前覆盖正常路径、可修复参数错误、同错误不同方案、真实失败、人工等待与恢复、暂停停止、撤权及报告分析入文。模型桩用于验证状态和边界；真实科学样例用于验证计算一致性。两者均不能替代正式网站操作。

最终验收必须使用正式网站的可视化界面，在真实用户项目启动、处理必要人工节点并完成任务，核对节点实际调用、主执行连续性、独立审核、分析正文及成果下载。服务器不可用时只记录本地验证，正式验收保持待办。
