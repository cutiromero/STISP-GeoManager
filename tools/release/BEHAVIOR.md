# 发布行为与联调边界

## 职责与冻结证据

`release.py` 是唯一命令入口，默认仅打印离线计划；`--execute` 才允许连接。`executor.py` 统一 SSH、SCP 和 origin 查询，使用密钥和严格主机指纹校验。工具不安装依赖、不改变 Git 状态，不自动清理旧发布或备份。

`artifacts.py` 导出精确 Git 提交，生成确定性完整包、增量包和清单；`migrations.py` 用 AST 静态分类；`compatibility.py` 在候选副本中运行基线检查及回滚事务 INSERT。`candidate.py` 和 `candidate_support.py` 管理独立候选和复制历史隔离；`server.py` 管理锁、身份、备份、切换和健康门禁；`protocol.py` 管理独立会话、接受证据、状态查询及显式回退。所有服务器工具逐文件摘要必须匹配清单。

清单绑定提交、前后端版本、包大小及 SHA-256、普通文件内容和权限、首页脚本、工具摘要、差异分类、服务器基线及接受回执。基线包含启动器和正式 TOML 摘要、四角色完整进程身份、worker 锁、受保护依赖进程、静态树及可信的 staged.json/filesDigest。本机 Git 基线源码加观测 dist 必须还原该摘要，不能用当前目录重新计算来代替历史证据。缺少正式完整提交或可信清单时停止，不从目录短 SHA 猜测。

已跟踪修改、未推送的精确 HEAD、固定个人分支不符均拒绝。未跟踪文件仅列入计划和本机记录，不自动入包。`local.buildResources` 白名单只用于构建前输入；资源缺失、路径越界或覆盖源码即停止，逐文件摘要记录，构建后移除输入副本。构建只借用已有 node_modules；前端复用必须核对旧包完整 dist 摘要。增量包从冻结基线重建，与完整包逐字节相同，不修改旧发布目录。

`fast --local-only` 不连接、不核实 origin、不生成正式接受声明；回执为 `localOnly=true`、`deployable=false`，不能绕过真实发布的脏工作区门禁。

## 迁移分类

分类比较基线和目标的 `backend/apps/*/migrations/*.py` 摘要；基线文件被修改、删除或改名直接拒绝。新增文件逐个解析 AST，不导入、不执行。拒绝结果记录文件、行号、操作及原因，并要求人工制定方案。

| 操作 | 自动发布规则 |
| --- | --- |
| `CreateModel` | 标准字段、可静态确认的实体表、选项、索引与约束；不允许与已知基线表重名，不支持动态 bases/managers、代理或 unmanaged 模型 |
| `AddField` | 已有模型仅可加可空列，或有非空字面量 `db_default` 的非空列；支持字面量 `models.Value`；Python `default` 不足以兼容旧 INSERT；不允许新增唯一列、主键或 OneToOne 约束 |
| `AddIndex` / `AddConstraint` | 只允许加在同一迁移已经新建的表上；已有表即使是普通索引也拒绝独立添加 |
| `RunPython` | 标准双参数函数、无装饰器及动态默认参数；可追踪 `apps.get_model`、`objects.using/filter/all/first`；仅对同迁移新表允许 `create/get_or_create/update`；允许读取基线表、取主键、字面量值和有限条件语句；`delete` 的 ORM 级联范围无法确认，其他未知调用或语句也拒绝 |
| `RunSQL` | 空 SQL，或向同迁移已新建表写入的单条 `INSERT ... VALUES`；值仅允许 SQL 字面量，逆操作只能为空；动态 SQL、表达式、子查询、多语句拒绝 |
| 空迁移 / `RunPython.noop` | 允许 |
| 删除、重命名、Alter 操作、已有表唯一约束、未知操作 | 拒绝；`SeparateDatabaseAndState`、外部函数和无法静态证明的语法不例外 |

分类写入 `migrationClassification`，包含基线摘要、新增集合、逐操作报告、受影响模型、基线提交及包 SHA-256。服务器在候选迁移前和正式门禁中重新读取源码分类，并要求与清单完全相同。`fast` 仍拒绝任何迁移变更，不复用 full 的兼容证明来放宽 fast。
`RunPython` 的 `.using()` 只能指向迁移连接的 alias 或 `default`，不得重绑定 `apps` / `schema_editor`；其他数据库别名不属于候选副本的隔离证据。

## full 候选验收

1. 校验正式基线、空间、端口、包摘要和文件清单；独立操作目录不得复用。正式元数据库在线备份为候选，复制 secret key，使用独立 TOML 和空科研根，保留 native 策略并禁用启动扫描。
2. 校验迁移源码及分类；候选副本迁移记录必须精确等于基线代码的已应用计划，基线不得有未应用项。
3. 仅对候选执行 `migrate`。全部记录必须为“基线加清单新增集合”，不得有多余、缺失或重复记录。
4. 记录 `databaseState`：按名称排序的表、列名/类型/非空/默认值/主键/隐藏列、外键、索引列/唯一性/来源/排序/部分索引，以及约束、视图和触发器 SQL 的规范化摘要。不包含数据、rowid、页面布局、schema_version 或迁移应用时间；迁移记录单独按 app/name 排序。
5. 在新进程加载基线代码，在内存中指定候选 TOML，不改写基线 `.runtime/config-path`。通过基线 `manage.py check`、只读迁移/模型查询；对涉及新增列的基线模型按旧列集执行 INSERT，不调用模型 save/信号。缺少必需关联行时在同一事务构造，未知字段或循环外键无法构造则拒绝。检查外键并回滚整个事务，核对原行数，不保留数据。
6. 原复制历史/会话隔离、新代码 `check`、`makemigrations --check --dry-run`、静态收集及归档、四角色启动和 HTTP/心跳/静态门禁、可选用户钩子保持必过。按身份停止全部候选进程；无法确认或停止时保锁转人工。
7. 候选结束再次核对结构和迁移记录未改变、正式身份未改变。`candidateAcceptance.migrationEvidence` 保存结构状态、基线迁移记录和兼容结果；它与分类、接受回执共同绑定同一包摘要，兼容结果还绑定基线提交及分类摘要。

## 正式切换顺序

1. 校验最终清单、工具和精确包、版本、完整接受 checks=true、独立发布目录。`noSchemaChanges=true` 仍要求迁移源码无变化；否则必须为 full、分类全部允许、同包候选结构与兼容证据完整且一致。
2. 解包新目录并核对冻结文件。基线迁移文件逐字节不变，新增文件和分类与清单精确相同。正式已应用记录必须精确等于基线计划，新增项全部未应用；新模型不得有遗漏迁移。
3. 持有双发布锁，核对进程、启动器、配置、worker 锁、受保护依赖和静态树；保持旧四角色服务直到活动队列排空，保留在线备份、公共前端依赖归档、独立静态准备及空间门禁。
4. 停 web、再次排空、停三个 worker，确认最终无活动任务；保存 `meta-quiesced.db` 及 SHA-256，写入回退上下文，重新核对迁移门禁，再执行正式 `migrate`。
5. 即使 `migrate` 抛错也必须核对结构身份：无迁移版本保留 schema_version 不变门禁；新增版本要求正式结构指纹和全部迁移记录逐项等于候选。之后再核对新代码迁移计划已全部应用。任何不匹配或不可读均为 `SchemaChanged`：保留 `DEPLOY.lock`、写人工回执，不自动启动旧角色。
6. 算子后置脚本仍按摘要核验，不自动登记或覆盖已发布算子；执行后再次核对结构。原子切换静态树和启动器两个 APP_ROOT，先启动 worker 后启动 web，通过原进程身份、锁/心跳、依赖服务、健康接口、首页 JS 摘要与 MIME 门禁，再核对数据库状态并接受。

## 自动恢复与显式 rollback

健康失败等可恢复错误先核对数据库结构证据，按原身份停止新进程，恢复代码、启动器、静态树和算子后置状态，启动旧代码并完成旧版健康门禁。结构已经前进但证据匹配时允许恢复旧代码；不执行逆迁移，不恢复、覆盖、删除任何数据库文件。回执的 `databaseAdvanced`、`databaseHandling`、`backup`、`quiescedBackup` 明确说明结构前进、旧代码兼容和静止备份位置，`databaseRestored=false`。

显式 `rollback` 只支持有完整证据的已接受版本：核对已接受提交、原清单、回退上下文、旧/新代码、旧启动器、备份摘要、正式配置和旧静态树 inode/内容；结构比旧代码新时重验同包分类、候选指纹、兼容结果及当前迁移记录。通过后仍需排空、在线/静止备份、停角色，再恢复旧静态树与启动器、按原身份启动并验收。恢复前、算子恢复后和健康检查后均核对数据库状态；结构身份不明或恢复失败保留发布锁并转人工。

回退不删除新增的迁移记录，因此旧代码目录不再代表数据库的干净迁移基线；后续 fast 不得将较新结构冒充旧状态。需要继续发布时，必须具有与实际数据库相符的基线证据。

## 状态与候选钩子

服务器独立会话使用独占启动标记避免重发；本机连接断开只重试只读 status，不重发切换指令。状态比较完整 PID 身份防止复用，不回传私有日志尾部。inspect 在角色缺失时报告 missing/ambiguous 与 `baselineVerified=false`；真实发布仍要求严格完整身份。活动队列仅查询活动状态，不扫描结束历史。

`--candidate-check /绝对路径/check.py` 仅用于 full，按冻结摘要运行。脚本接收 `--context <候选上下文 JSON>`，最后一行必须为 `{"accepted":true,"checks":{"业务验收":true}}`，checks 非空且全部 true，默认超时 600 秒。不得放宽迁移、备份、隔离或正式门禁；依赖必须预先准备。

真实联调包括服务器身份与权限、上传重建、SSH 断线持续执行、候选完整副本与业务钩子、真实排空竞争、SQLite 在线/静止备份、正式迁移指纹、静态原子切换、四角色健康、受控自动回滚和显式回退。离线桩不能代替这些验收。
