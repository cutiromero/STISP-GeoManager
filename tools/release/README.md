# 标准发布工具

所有命令默认只打印完整离线计划，**不会连接服务器**；包括只读命令在内，只有 `--execute` 才连接。仅使用 SSH 密钥与严格主机指纹校验，不接收口令，不自动安装依赖、不改 Git 状态。
未提供 `--config` 且缺少默认本机配置时，纯离线计划明确使用样例；执行或 local-only 模式仍要求配置存在，显式指定的无效配置不回退。

首次将 `tools/release/config.example.toml` 复制为 `config/release.local.toml`，在沙箱外核实并替换所有 `REPLACE_` 路径，预先准备 SSH 公钥、known_hosts 和本机前端依赖。真实配置已被 `.gitignore` 排除。

```bash
PYTHON=/opt/homebrew/Caskroom/miniconda/base/envs/stisp-geomanager/bin/python
$PYTHON tools/release/release.py inspect --execute
$PYTHON tools/release/release.py fast --execute
```

前端构建会调用仓库里的 Python 脚本；工具把运行自身的解释器所在目录放在构建环境 `PATH` 的最前面，因此必须用上面的项目解释器运行。候选端口由本机配置 `[candidate].port` 指定，须为服务器上空闲的端口。

构建禁用 Python 字节码缓存，避免临时导出目录中的 `__pycache__` 进入归档。遇到频繁创建 SSH 连接导致传输断开时，可在本机 `[ssh].options` 同时增加 `ControlMaster=auto`、`ControlPersist=60` 和 `ControlPath=/绝对私有目录/control`，使 SSH 与 SCP 复用同一条认证连接。套接字父目录必须由当前用户持有、权限为 `0700`；仍保持密钥认证与严格主机指纹校验，连接空闲60秒后退出。

| 命令 | 用途 |
| --- | --- |
| `inspect` | 正式根、SHA、版本、四类进程、队列、磁盘、双锁，以及本机 Git 差异 |
| `fast` | 已跟踪文件干净且精确 HEAD 已推送 → 英文临时目录导出 → 正式构建或摘要核对复用 → 增量上传 → 独立会话切换 → 硬验收 → 回执 |
| `full` | 在切换前增加独立候选副本、历史隔离、迁移、四角色及 HTTP/静态验收；可追加 `--candidate-check /绝对路径/check.py` |
| `status` | 离线显示本机记录位置；`--execute` 只读查询相同服务器最近作业，重启本机工具不影响服务器会话 |
| `rollback` | `--execute` 排空并备份当前状态，核实旧代码/配置/schema/静态摘要后恢复上一根目录、启动器和静态树，不还原数据库 |

常规发布运行 `fast --execute`。已跟踪文件有已暂存或未暂存修改、origin SHA 不一致会直接停止；未跟踪文件不阻断，在计划、清单和本机回执中列出，不自动带入源码包。含任何迁移、科学算子改动或非祖先会提示使用 `full`。**full 仅自动接受新增且兼容旧代码读写的迁移，任何不能静态证明安全的操作都拒绝。** 算子代码进入发布包，不自动登记/覆盖已发布算子版本。

## 新增型数据库迁移

- 允许新建实体模型、增加可空列或具有非空 `db_default` 的非空列；索引、唯一及其他约束操作仅允许作用于同一迁移新建的表。Python `default` 不等于数据库默认值。
- `RunPython` 仅接受可追踪模型来源的有限 ORM 操作，写入必须落在同一迁移新表；可读取基线表。`RunSQL` 仅接受向同一迁移新表写入的单条字面量 `INSERT ... VALUES`，不接受表达式、子查询、多语句。空迁移和显式 noop 允许；其余语法不能证明安全则拒绝。
- 删除、重命名、修改已有列、基线迁移源码变化、已有表唯一约束及未知操作均拒绝，报告文件、行号、操作和原因，要求人工制定方案。静态分类使用 Python `ast`，不导入或执行迁移代码。
- 候选先在正式库副本迁移，记录无数据的规范化结构指纹和迁移记录；使用基线代码运行 `manage.py check`，读取基线模型，并在一次必定回滚的事务中按旧列集插入涉及新增列的模型。分类、指纹、兼容结果及候选接受回执绑定同一个包 SHA-256。
- 正式切换保留排空、双锁、备份和健康门禁。静止备份后才执行 `migrate`，再核对结构指纹和全部迁移记录与候选一致，之后才能切换静态树与启动器。基线迁移文件必须逐字节不变，新增文件集合必须与清单相同，迁移前正式已应用记录必须精确等于基线。
- 健康失败只回退代码、启动器和静态文件，**不执行逆迁移、不恢复任何数据库**。回执注明“数据库结构已前进，旧代码经兼容检查可运行”，并保存静止备份路径。显式 `rollback` 对较新的结构核对同一证据、结构指纹及迁移记录后才允许回退。

`local.pnpm` 是命令参数列表，默认前缀与 `scripts/verify_fast.py`、AGENTS.md 一致：`pnpm --config.verify-deps-before-run=false --config.manage-package-manager-versions=false`；工具不执行依赖安装或修改锁文件。

`local.buildResources` 是尚未进入 Git 的额外构建输入路径列表，默认 `[]`。团队照片和成果展示图随源码保存在 Git 中，通过 Git 导出目录直接参与构建，无需列入该配置。重建仍依赖外部素材的历史提交时，可按对应发布清单填写额外资源；工具在构建前复制这些文件，缺少文件即停止，逐文件 SHA-256 写入清单和 `build-resources.json`，构建后删除额外输入副本。额外资源不得覆盖已跟踪源码，亦不得直接写入 dist 或 node_modules。

切换失败自动恢复代码、启动器和静态树；结构指纹或迁移记录偏离候选、结构身份不可读、进程身份不明或恢复失败则保留 `DEPLOY.lock`，转人工，不自动启动旧代码。先运行 `status --execute`，检查回执给出的阶段及远端操作目录 `driver.private.log`；不删除锁、不反复发起切换。显式回退只支持本工具创建且保留完整回退证据的已接受版本；旧现场脚本发布的版本仍可作为首次发布基线，但不能凭空生成回退证据。回退后的数据库保留新增迁移记录；不得把它冒充为旧代码的干净迁移基线继续 fast 发布。

本机证据位于 `.runtime/releases/<UTC时间>-<短SHA>-<随机标识>/`，只保存清单、回执及日志；源码与包仅在系统临时目录，退出即删除。服务器保留独立发布目录、备份与私有日志，不自动清理旧版本。实际切换在服务器独立会话运行，本机定期轮询到三种终态之一；临时 SSH 中断只重试只读查询，不重发切换命令。

离线验证：`$PYTHON -m pytest tools/release/tests`。仅验证本机阶段：`fast --local-only --base-commit <已知基线SHA> --baseline-package <该SHA的完整包>`；可用 `--commit <SHA>` 验证历史提交。该模式不连接、不核实 origin、不生成可部署或接受回执，不能绕过真实发布门禁。完整行为差异、原脚本映射及钩子协议见 `tools/release/BEHAVIOR.md`。
