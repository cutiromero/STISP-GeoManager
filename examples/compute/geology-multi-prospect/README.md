# 修正后找矿远景区分析

版本2.1.0。使用`../geology-multi-core/build.py`构建独立ZIP，仅登记本算子新版本，保留已登记的其他算子包与历史任务。

仅接收修正后岩性、构造、矿物识别及批准权重，当前交汇、研究范围和明确绑定的规则。没有修正前找矿输入，不分A/B等级。

P-02必须声明`evidence_method=weighted_neighborhood_presence_v2`。每种矿物在分析格网内取有效识别像元的最大批准权重，再取`search_m`圆形格网中心邻域内最大权重。每种矿物只计一次；累加达到`min_types`，且位于有效构造支持范围和已知基岩岩性内，才能成为候选。零权重和剔除像元不参与。邻域出现不表示同像元共存，分析网格决定距离近似精度。

默认100米格网、250米邻域、加权类型数2，最小面积20万平方米、最大面积300万平方米，四邻域连通圈区。按平均加权矿物组合强度、有利岩性覆盖、面积排序，最多保留5处，统一编号P001等。超大连通区直接记录在筛选诊断中，不切成任意方块充当目标。

每区输出实际条件、矿物权重及知识引用。`quality.json`保留逐层筛选数、面积和数量限制以及空结果原因。

`prospect_support.tif`仅在保留目标内生成连续相对置信度：原始支持度为0.7×加权矿物类型数/参与矿物数+0.3×有利岩性，构造与基岩条件为先决条件；按一格高斯核在目标内归一化平滑，再在保留目标的范围内归一化至0—1，均匀时为0.5。背景为NoData，不扩大目标。后端统一脚本蓝—黄—红连续赋色。相对置信度为证据支持度，不是矿化概率。

每种矿物只读取一次，逐区证据复用格网。全部结果限定研究区，原始资料不改动，支持真实空结果。

平台SDK提供与当前任务文件身份绑定的已核验证据标识时，复用像元、掩膜及权重标识，避免重复全幅扫描；独立调用仍计算实际标识。两条路径的科学输入快照、规则处置与输出语义一致。
