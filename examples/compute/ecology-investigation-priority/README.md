# 生态分区统计与调查优先级

`run(context)` 接受 `change` 单波段NDVI差值、`zones` 有唯一非空 `zone_id` 的有效面矢量、`context` UTF-8 CSV。变化栅格采用米制投影和[-2,2]差值尺度，NoData与非有限值排除；分区投影至栅格CRS进行平面面积统计，输出矢量保留原分区属性、几何和CRS。

## 表格契约

CSV必需表头：`zone_id,date,event_type,land_use,evidence_id,source,confidence,value`。允许附加说明字段。一行一条背景或观测，同一分区的 `evidence_id` 唯一；`confidence` 为[0,1]数字，空值按0处理。`date` 为 YYYY-MM-DD，`source` 为可追溯资料位置。模拟观测在来源和附加说明中注明。

- `background`：背景信息，`land_use` 可用 `cropland` 等类型，`value` 可为文字说明。
- `harvest`：收获观测；仅 `land_use=cropland`、日期落两期闭区间、可信度达标、有来源及证据ID时支持收获解释。`value` 可为1或收获说明；0、负值、false/no/未发生/未收获不计为发生。
- `drought`、`water_shortage`：演示观测严重度，`value` 为[0,1]。该数值须由明确演示规则或资料评价给出，原始毫米等物理量先按相应方法解释。
- `rainfall`、`observation`及其他类型：匹配后保留证据关联，模型结合原资料解释；初版排序未给这些物理量另设换算公式。

日期不匹配、区域不匹配、来源/证据ID缺失或可信度不足的记录不改变排序。输入时段来自变化栅格 `early_date/late_date` 标签；缺标签时显式提供同名参数，参数与已有标签不一致则拒绝。空数据行列表可以只有完整表头，表示尚无观测。

## 明示的演示规则

统计采用每个栅格像元四边形与分区面的实际相交面积作为权重，包括边缘部分像元。`total_area_m2` 为整个分区面积；`valid_area_m2` 为分区内实际共同有效面积，区外栅格覆盖缺失也降低覆盖率。`mean_change` 是有效面积加权的平均差值，`decline_area_m2` 为差值≤阈值的有效面积（允许1e-7的float32舍入误差），`decline_fraction=下降面积/共同有效面积`。

最低覆盖率默认0.65；不足或无有效像元的区域标记“优先补资料”，不进入调查排名。其余分区按以下实际数值排序（高分优先、同分按输入顺序）：

1. 基础分：`(下降权重×下降占比 + 均值权重×max(0,−平均差值)/2)/(两个权重之和)`，默认权重0.7、0.3。
2. 干旱/缺水支持：同区同期间可信记录中 `max(value×confidence)`，乘默认0.15后加至基础分；重复同类观测不累计堆高分数。
3. 收获解释：基础分乘 `1−收获减分强度×max(匹配收获confidence)`，再加上第2步的干旱/缺水支持量，默认减分强度0.75。收获解释降低植被变化分量，可信干旱/缺水观测仍保留自身加分。

所有权重、下降阈值-0.15、可信度门槛0.7及覆盖率门槛均在算法清单中可调，属于本次演示方案；算法不使用区域名字、固定编号或预设调查答案。

`priority.gpkg` 的 `priority` 图层和 `zone-statistics.csv` 包含分区统计、`priority_class/rank/score`、逐区 `reason`、`evidence_ids`、`evidence_sources`、时期、基础分及两类观测支持量，便于地图点击和模型读取。覆盖不足时排名为空。`quality.json` 使用平台质量协议；`passed` 表示统计和明示规则执行正确，调查分数用于安排排查顺序。

本算法在内存处理小范围演示资料。两期变化的原因与持续退化结合更多观测、长期序列和现场核查；绿光—近红外NDWI提供辅助水体信息，根区土壤水分使用相应观测。
